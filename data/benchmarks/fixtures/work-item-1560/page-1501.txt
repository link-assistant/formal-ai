  Agent mode 0.355.27 misroutes common file requests: typo 'corrent' becomes a path, 'delete all files' and 'search for TODO' run ls, 'how many files' runs pwd, shell lines pass through verbatim #1501New issueCopy linkNew issueCopy linkOpen#1502OpenAgent mode 0.355.27 misroutes common file requests: typo 'corrent' becomes a path, 'delete all files' and 'search for TODO' run ls, 'how many files' runs pwd, shell lines pass through verbatim#1501#1502Copy linkDescriptionkonardopened on Nov 1, 2026Issue body actionsSummary
Found while building the experimental --use-formal-ai mode of start (link-foundation/start#255, PR link-foundation/start#256). In that mode, start sends a natural-language request to Formal AI's OpenAI-compatible agent endpoint and runs the bash tool calls it returns, without a shell and under an effect policy.
With Formal AI 0.355.27 (commit 4d57ec7b, node js/server/main.mjs --agent-mode, Node.js v26.13.0), several common requests are routed to the wrong tool call. start reports the real outcome, so nothing unsafe happens, but the tasks are not done.
Reproduction
H=$(mktemp -d)
HOME=$H FORMAL_AI_MEMORY_PATH=$H/m.lino node js/server/main.mjs --agent-mode --host 127.0.0.1 --port 18080 --silent &amp;
curl -s http://127.0.0.1:18080/api/openai/v1/chat/completions -H 'content-type: application/json' -d '{
  "model": "formal-ai",
  "messages": [{"role": "user", "content": "print list of files in corrent directory"}],
  "tools": [{"type": "function", "function": {"name": "bash", "description": "Run a shell command",
    "parameters": {"type": "object", "properties": {"command": {"type": "string"}}, "required": ["command"]}}}]
}'
For the second turn, send the assistant message back with a tool message such as &lt;untrusted_context&gt;\nCommand: ls\nDirectory: /tmp/x\nOutput: a.txt\nb.txt\nError: (none)\nExit Code: 0\n&lt;/untrusted_context&gt;.
Observed tool calls



Request
Tool call returned
Expected




print list of files in current directory
ls
ls ✅


print list of files in corrent directory (typo from the start issue)
ls 'corrent', which exits 2
ls. The typo should be recognized as "current", not taken as a path.


delete all files
ls. The second turn is finish_reason: stop with "The ls command completed. Output: …"
Either the requested deletion (subject to the caller's policy) or an explicit "not supported". A listing should not end the turn as if the task were done.


search for TODO in all files
ls
grep -rn TODO .


how many files are in the current directory
pwd. The second turn says "The pwd command completed" and quotes the result but gives no count.
A listing followed by a count.


show the first 5 lines of README.md
cat README.md
head -n 5 README.md


ls; rm -rf ~
ls; rm -rf ~ (the request text passed through verbatim)
The request should not be forwarded unmodified as a shell line. start refuses it (it never uses a shell), but other agent hosts might run it.



Impact on start
start reports the real status: for example, the last tool call exited with 2 for the typo, and finished after 1 tool call(s); no file changed for delete all files. These requests therefore fail visibly rather than silently. The start documentation lists them as known limits of Formal AI 0.355.27.
