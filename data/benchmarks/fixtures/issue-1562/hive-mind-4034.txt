"Context and tokens usage" shows output above 100%: cumulative session output is divided by the per-response output limit

## What happens

The "Context and tokens usage" line of the log comments shows an output percentage far above 100%. Examples from two runs of solve v2.39.10 on 2026-11-10 (`--tool agent` and `--tool claude`; the provider in both runs is Formal AI, but the arithmetic below does not depend on the provider):

| Comment | Usage line | "Total" line of the same comment |
|---|---|---|
| https://github.com/konard/test-hello-world-019fb330-00e1-73b9-955e-f357a1600d5b/pull/2#issuecomment-6762659771 | "29.5K / 54050.5M (0%) input tokens, 80.0K / 8.2K (976%) output tokens" | "Total: 461.2K input tokens, 80.0K output tokens" |
| https://github.com/konard/test-hello-world-019fb330-00e1-73b9-955e-f357a1600d5b/pull/2#issuecomment-6762815699 | "29.9K / 54050.5M (0%) input tokens, 31.1K / 8.2K (380%) output tokens" | "Total: 222.2K input tokens, 31.1K output tokens" |
| https://github.com/konard/test-hello-world-019fb330-fa49-7c9d-a664-b7ea33bb698a/pull/2#issuecomment-6763700936 | "41.2K / 200K (21%) input tokens, 73.4K / 32K (229%) output tokens" | "Total: 522.8K input tokens, 73.4K output tokens" |

In each row the output numerator equals the session total (80.0K, 31.1K, 73.4K), while the input numerator (29.5K, 29.9K, 41.2K) is much smaller than the session total (461.2K, 222.2K, 522.8K). The two halves of one line use different kinds of numbers.

The first pull request has nine comments with an output percentage above 100%, going back to 2026-08-02 (for example https://github.com/konard/test-hello-world-019fb330-00e1-73b9-955e-f357a1600d5b/pull/2#issuecomment-5158416506, "26.0K / 8.2K (317%)").

A value below 100% is produced the same way and is equally misleading: "23.3K / 32K (73%) output tokens" in https://github.com/konard/test-hello-world-019fb330-fa49-7c9d-a664-b7ea33bb698a/pull/2#issuecomment-6763636762 is also a session sum against a per-response limit.

## Expected

A percentage compares like with like and cannot exceed 100% for a session that completed normally: either the largest single response against the per-response output limit, or the cumulative output without a limit and without a percentage.

## Root cause

Code read at 2.39.14 (commit b245deb62fbbca42625753587575416c50d81727). The evidence runs are 2.39.10; whether the cited lines are identical in 2.39.10 was not verified.

[`src/claude.budget-stats.lib.mjs` lines 590-602](https://github.com/link-assistant/hive-mind/blob/b245deb62fbbca42625753587575416c50d81727/src/claude.budget-stats.lib.mjs#L590-L602), `formatContextOutputLine`:

```js
const outPct = ((outputTokens / outputLimit) * 100).toFixed(0);
parts.push(`${formatTokensCompact(outputTokens)} / ${formatTokensCompact(outputLimit)} (${outPct}%) output tokens`);
```

Caller, lines 724-730:

```js
const peakContext = getDisplayContextInputTokens(usage);
...
stats += formatContextOutputLine(peakContext, contextLimit, usage.outputTokens, outputLimit, '- ');
```

The input side is a per-request peak. The output side is `usage.outputTokens`, the sum over the whole session, divided by `usage.modelInfo?.limit?.output`, the limit of one response. Lines 753-754 repeat the same division.

## Suggested fix

- Track the largest output of a single response (as is done for the input peak) and use that as the numerator, or
- when no per-response peak is known, print the cumulative output without limit and percentage, the way the comment of the `--tool codex` run of the same day reads ("225.2K / 272K (83%) input tokens", then "Total: 225.2K input tokens, 43.3K output tokens" in https://github.com/konard/test-hello-world-019fb331-c107-78c7-8ff6-9f127a3c593c/pull/2#issuecomment-6763530262).
- Add a test with several responses whose outputs sum above the limit while each stays below it; the line must not exceed 100%.

Not part of this report: the context limit "54050.5M" in the first two rows. Where that value comes from was not examined here.
