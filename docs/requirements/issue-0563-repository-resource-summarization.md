## Issue #563 Repository Resource Summarization

Issue [#563](https://github.com/link-assistant/formal-ai/issues/563) asks the
summarization pipeline to handle arbitrary repository files, formalize each file
before summarizing it, recurse into Markdown embedded grammars, and preserve the
issue research under `docs/case-studies/issue-563`. PR
[#564](https://github.com/link-assistant/formal-ai/pull/564) adds a repository
file formalization boundary on top of the existing deterministic
`formalize -> summarize -> deformalize` pipeline. New rows R345-R354 capture the issue-specific obligations; each is implemented and covered by the tests its row names, with the documents covered by `rust/tests/unit/docs_requirements/issue_563.rs`.

Review feedback on PR #564 (konard) made the generalization explicit: the
solution must not stay file-specialized, but follow the meta algorithm —
describe the task, formalize it to the meta language, decompose, solve, and
compose — so that *any* repository resource can be summarized, **including
folders**, not only files. Rows R355-R359 capture this generalization, implemented and covered by `rust/tests/unit/specification/summarization_pipeline.rs` and the source-mirror tests each row names: a
directory is summarized by the recursive decompose -> summarize -> compose loop
(`rust/src/summarization/resource.rs`), with recursion depth bounded by the
summarization mode ladder.

JavaScript twin (PR #1188, 2026-10-08, JavaScript-first doctrine R997): `js/agentic/crate/summarization.mjs` (mirrors `mod.rs`), `summarization_markdown.mjs`, `summarization_dialog.mjs`, `summarization_file.mjs`, `summarization_resource.mjs`, `summarization_identifier.mjs` and `summarization_vocabulary.mjs` port the #563 surface, with every wording read from `data/meta/agentic-messages.lino` and the summary-cue meanings. `rust/tests/web/issue-0563-repository-summarization.test.mjs` replays the Rust tests named below on the same inputs and committed fixtures, plus conversation summaries captured from the prebuilt `formal-ai` 0.347.0 binary. Not yet at parity: the `meta_language` parse evidence of a code file, which the Rust build takes from the `meta-language` crate for 17 grammars; the JavaScript root carries it only for Rust (`summarization_meta_language.mjs` over the vendored tree-sitter-rust), no host installs that parser by default, and its four numbers are pinned by shape, not by a native run. `describe_project` and the #844/#893 layers (`importance`, `context`, `dedup`, `recheck`, `pipeline`, `gathering`, `validation`) have no JavaScript twin yet.
