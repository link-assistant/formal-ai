## Issue #701 Auto-Learning Adoption Gap

Issue [#701](https://github.com/link-assistant/formal-ai/issues/701) (E59) reports
that the auto-learning loop *observed* its own failures without ever adopting a
fix: the Google Trends frontier stayed at 60 unanswered prompts, and a retained
dreaming amendment appended a compliance line without changing how the task was
solved. PR [#817](https://github.com/link-assistant/formal-ai/pull/817) closes
the gap end to end — a learning cycle that derives, validates, and proposes;
a ledger that proves each capability delta; and a periodic, human-gated run.

| ID | Requirement | Status |
| --- | --- | --- |
| R701-1 | Define the adoption contract: take a frontier item, derive candidate knowledge, validate it against generated tests, and emit a promotion proposal in the exact shape issue #656 consumes. | `src/learning_cycle.rs` implements the cycle; `formal-ai learn cycle --frontier google-trends --dry-run [--proposals]` runs it. Candidates are request-opener surfaces derived from the frozen frontier record, each validated against held-out prompts of the same class before it may be proposed; proposals are rendered by `render_promotion_proposals` and round-trip through `parse_promotion_proposals`. Covered by `the_learning_cycle_emits_promotion_proposals_in_the_issue_656_shape` and `the_cycle_is_deterministic_and_reproducible_offline`. |
| R701-2 | Record a before/after capability pair for every adopted item, in all supported languages. | `data/meta/learning-adoption-ledger.lino` records 60 pairs across 10 topics and 4 languages, each with `before_intent "unknown"` and the routed `after_intent`. Generated by `cargo run --release --example issue_701_adoption_ledger` and byte-pinned by `committed_adoption_ledger_matches_a_fresh_run`; the class claim is checked by `the_adoption_ledger_records_a_real_capability_delta_in_every_language`. |
| R701-3 | Drive the issue #498/#499 Trends frontier through the loop until the corpus answers, or record each failure as a named blocking gap. | The corpus answers 80/80: `data/meta/google-trends-learning.lino` reports `handled_by_engine "80"` and `learning_frontier "0"`, down from 60 unrouted. The `intent: unknown` rate over the committed corpus fell from 7500 to 0 basis points and is ratcheted by `the_trends_corpus_unknown_rate_is_ratcheted_to_zero`. |
| R701-4 | Dreaming amendments must change solving behaviour through the production path; delete any decoration-only code path. | `append_amendments` now reclassifies a covered task instead of only decorating it — a task matched by a retained standing requirement is never returned as unresolved (`STANDING_REQUIREMENT_INTENT`). The three application paths share one selection rule (`matching_amendments`) and one projection (`amendment_lines`); the duplicated `matching_amendment_lines` decorator is deleted. `tests/unit/issue_701_dreaming_amendment_class.rs` raises the single-prompt issue-#540 check to a class-level suite: 3 topics × 4 languages of held-out paraphrases through both protocol surfaces, plus a negative control proving an uncovered task comes back byte-identical. |
| R701-5 | Run the loop periodically in proposal mode by default, honouring the human gate. | `dreaming_runtime::write_learning_cycle_record` leaves a proposal-only record next to the memory log on every idle run, and `.github/workflows/learning-cycle.yml` replays the cycle daily, asserting `mode "proposal_only"`, `human_gated "true"`, and that no seed file changed. Covered by `every_idle_dreaming_run_leaves_a_proposal_only_learning_cycle_record`. |
| R701-6 | Preserve every failure to adopt as a durable frontier record, consistent with R425. | `data/meta/learning-frontier-google-trends.lino` freezes the 60 pre-adoption verdicts even though the live frontier is now empty, and every candidate rejected by its held-out tests is recorded as a blocked class rather than dropped. Covered by `every_failure_to_adopt_is_preserved_as_a_durable_record` and `the_frozen_frontier_record_spans_every_supported_language`. |
