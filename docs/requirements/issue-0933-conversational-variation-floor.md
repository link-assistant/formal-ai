## Issue #933 Conversational Wording-Variation Floor

Issue [#933](https://github.com/link-assistant/formal-ai/issues/933) is the CI
enforcement that issue
[#123](https://github.com/link-assistant/formal-ai/issues/123) asked for and
PR [#124](https://github.com/link-assistant/formal-ai/pull/124) did not deliver:
every conversational test case must hold at least five distinct wording
variations in each of `en`, `ru`, `hi` and `zh`. The corpus is data
(`data/benchmarks/conversational-variations-suite.lino` plus its per-language
partitions), the count is a CI gate
(`tests/e2e/scripts/check-conversational-variation-floor.mjs`), and every
recorded prompt is answered by the real engine
(`tests/unit/conversational_variations.rs`). Evidence, the "before" measurement
and the dedup analysis against the existing language checks are in
[`docs/case-studies/issue-933/`](../case-studies/issue-933/README.md). The
requirement IDs below are the ones used in that case study.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R933-1 | "Wording variation" is machine-checkable, not a convention in comments. | Implemented: a manifest declares the cases, the languages and `minimum_variations_per_language`, and each prompt is a `conversational_variation_case` record carrying its case, language, expected intent, expected evidence link and expected answer. The Agent-authored contract in `data/meta/conversational-variation-floor-contract.lino` defines the equivalence rule: NFKC then lowercase, discard Unicode punctuation/symbol/separator categories and whitespace, and preserve letters, numbers and combining marks. |
| R933-2 | A CI script walks the corpus and fails if any test case holds fewer than five variations in any advertised language. | Implemented: `npm run --prefix tests/e2e check:variation-floor`. It also rejects duplicate ids, unlisted cases or languages, records in the wrong partition, prompts that are empty once punctuation is stripped, prompts that only re-punctuate one already counted, and records that show no answer. |
| R933-3 | Under-covered cases are backfilled until the check passes. | Implemented: 10 cases × 4 languages, 228 prompts, smallest group 5. The router phrasings the backfill needed were added to `data/seed/intent-routing.lino` and `data/seed/meanings-intent.lino`; 8 of 24 groups in the previous corpus were below the floor (`docs/case-studies/issue-933/raw-data/legacy-counts-before.txt`). |
| R933-4 | The check runs in CI. | Implemented: `data/meta/ci-gates/check-conversational-variation-floor.lino`, stage `web`, run by `rust-script scripts/run-ci-gates.rs --stage web` from `.github/workflows/release.yml` (issue #991 replaced the workflow's step list with this registry). |
| R933-5 | A unit test covers the counting logic with fixture data engineered to trip the floor. | Implemented: `tests/web/conversational-variation-floor.test.mjs` — a group at four, a language with no records at all, five re-punctuated copies of one phrase that must count as one, and a record that shows no answer. |
| R933-6 | Manual check: reducing one case to four variations in one language fails locally. | Implemented: `docs/case-studies/issue-933/raw-data/floor-check-manual-failure.txt` (Node gate, exit 1) and `rust-corpus-manual-failure.txt` (the Rust half of the same deletion). |
| R933-7 | Coverage counts print per language on every run. | Implemented: the count table prints on success as well as failure — `docs/case-studies/issue-933/raw-data/floor-check-pass.txt`. |
| R933-8 | A failure names exactly which cases are under the floor. | Implemented: one `- case <name> has <n> <language> variation(s); the floor is 5` line per shortfall, followed by the file to edit. |
| R933-9 | Standing clauses: a case study under `docs/case-studies/issue-933/`, delivered as a single pull request. | Implemented: the case study and PR [#1010](https://github.com/link-assistant/formal-ai/pull/1010). |
| R933-10 | The new gate does not duplicate `check:language-test-coverage`. | Confirmed: that gate is diff-aware and satisfied by one mention of each registered language in a pull request's added test lines; it can never observe a case stuck at four wordings. Full comparison against it, `check:language-change-parity` and `check:intent-coverage` in the case study. |
| R933-11 | Every recorded variation is one the engine actually routes, and it shows the exact answer that wording produces. | Implemented: `tests/unit/conversational_variations.rs` answers all 228 prompts with `FormalAiEngine` and asserts intent, evidence link and the recorded `expected_answer` verbatim (`expected_answer_contains` for the multi-paragraph capability listing and for arithmetic values). Counting alone cannot be satisfied with wordings the router rejects, and a corpus that records answers is documentation as well as a floor (R234-2). |
| R933-12 | The recorded answers are complete in every advertised language. | Fixed: recording the answers surfaced sixteen Hindi and Chinese prompts answering with an empty string, and Russian and Hindi wellbeing answers losing their closing sentence, while English was untouched. Root cause in `src/question_necessity.rs` (a sentence boundary required whitespace after the stop and did not know the Devanagari danda; corner brackets and parentheses did not shield a quoted example) and in `data/seed/question-necessity.lino` (requirement cues covered the English follow-ups only). Regression test: `tests/unit/issue_933_answer_parity.rs`, five tests that all fail on the unfixed engine, plus a sixth pinning the Spanish seed answers, which the floor does not cover because `es` is registered `status partial`. |
| R933-13 | Execute part of the issue through Formal AI and the real Agent CLI: attempt the whole task, split only from failure until the leaves are solvable, climb back up, and learn from those same sessions without self-promotion. | Implemented: `experiments/issue_933_self_authoring/run.sh` captures five real Agent-CLI sessions in `docs/case-studies/issue-933/self-hosting-authorship/`: whole failure, three passing leaves, passing parent retry. Two of six deliverable leaves are Formal-AI-authored (33%). `src/orchestration/incremental.rs` now feeds every run's exact sessions to proposal-only client-contract learning; this run's `learning.lino` reports five observations and four `awaiting_human_review` proposals. `tests/unit/issue_933_self_authoring.rs` and `tests/integration/issue_991_incremental_dispatch.rs` pin the artifact and general lifecycle. |
| R933-14 | Node and Rust implement the normalization contract identically for compatibility characters and combining marks. | Fixed: Rust now applies NFKC and discards the same Unicode P/S/Z category families and whitespace as Node, while preserving combining marks. Both regression suites assert `Ａ == A`, `１ == 1`, and `क != का`; before the fix Rust disagreed on the fullwidth examples and collapsed the Hindi pair. |
