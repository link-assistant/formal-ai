## Standing Doctrine: JavaScript First, Full Parity, Then Translate (2026-10-06)

Stated by the project owner while continuing PR #1188 (quoted in
[the 2026-10-06 architect note](../architect-notes/2026-10-06-javascript-first-full-parity.md)).
It sharpens the 2026-09-24 three-roots doctrine (R992-R996): JavaScript is not only a full root
but the **first** one. Requirements are implemented and tested in JavaScript
first, and Rust follows by translation through the meta language — or, until
the translator covers a construct, by a port that names its JavaScript
original. The stated reason is the same iteration speed, plus local resources:
Rust builds run in CI on push, not on the developer machine.

| R1000 | The js → ts leg of translation runs in JavaScript (`scripts/translate-es.mjs`, a byte-for-byte twin of `rust/src/es_tokenizer.rs` + `es_meta.rs` `write_source`), so `ts/` regenerates without compiling the crate; CI proves the two translators render identical bytes. New JavaScript handler modules are written in the portable subset link-foundation/meta-language's JavaScript → Rust translator accepts (top-level functions with JSDoc types, `const`/`let`, tagged unions dispatched by `switch`, no classes, generators or destructuring) so the js → rust leg becomes mechanical when that translator is released. | js → ts twin delivered 2026-10-06 (`rust/tests/web/translate-es.test.mjs`, layered-ci ts and rust tiers). js → rust is partial, re-measured 2026-10-08: 249 of 2,369 items in scope translate, and only 24 of them are functions (the rest are constants). The output is committed as test fixtures only, so rust/src stays hand-ported and the loop is not closed until generated Rust replaces the hand twins. It runs through the upstream translator: [meta-language#196](https://github.com/link-foundation/meta-language/pull/196) was merged on 2026-10-06 but is unreleased, so `scripts/translate-js-rust.mjs` runs `selfTranslate` from meta-language main pinned at `679a3b3c` (`data/meta/js-rust-translation.lino`; the layered-ci `js-rust` job checks out that commit). Over the 128 agentic crate and meta reasoner modules, 249 items translate and 2,120 are carried; 79 modules translate at least one item, one translates whole, and 49 are refused. Outside the scope, the planner, server and worker (233 modules) translate 819 of 6,564 items, 59 of them functions, so the scope is not widened (`docs/case-studies/pull-request-1188/js-rust-translation-scope.md`, measured with `experiments/formal_ai_subagent/translation-scope.mjs`). Translation-friendly rewrites of the crate JavaScript (`for (let …)` loops, loops with sentinels for `.find`/`null`) were measured in sandbox copies and gained no item, so none was committed. The committed projections (`rust/tests/fixtures/js-rust-translation/`) must re-render byte for byte. All of them compile with rustc, and 72 constant and call assertions hold in the translated Rust. A module's translated count never falls, and its inferred-signature count never rises. Pinned by `rust/tests/web/js-rust-translation.test.mjs` and the `check_js_rust_translation` gate.
