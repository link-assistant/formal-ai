## Issue #1021 Full-Range Coding And Contribution Artifacts

Issue [#1021](https://github.com/link-assistant/formal-ai/issues/1021) collects
the prompts Formal AI answered wrongly, the capabilities a contribution needs to
land, and the demand that the whole loop be test-covered in one pull request.
See PR #1027 and `docs/case-studies/issue-1021/`.

The rule the issue states first governs every row below: "solve by
generalization, not specialization -- a per-prompt fix that makes one task pass
is a regression against that instruction, not progress". Rows marked **not
delivered** are reported rather than quietly narrowed, per the issue's own "the
bar is not to be met by lowering it".

| R1021-3 | #868: a bare `ls` is the request, not a fragment. | `bare_shell_tokens` reads the terminal-command catalog, so an argument-free command routes to `exec_command` (`a_bare_command_is_the_request`). |
| R1021-4 | #866/#867: `Execute ls command` runs `ls`, not `ls command`. | The command-naming noun is declared per language in `data/seed/terminal-commands.lino` and stripped before the passthrough (`a_command_naming_noun_is_not_an_argument`). |

| R1021-26 | File upstream issues with reproductions for defects that are not ours. | [openai/codex#39487](https://github.com/openai/codex/issues/39487): from `@openai/codex@0.148.0` on, the ENTER answering the first-run trust dialog is dropped if it arrives as the dialog renders. Reproduced without Formal AI by `experiments/issue_1021_codex_tui_version/codex_trust_dialog_probe.py`; the bisect through the real harness is `run.sh` beside it. Every *other* root cause in this case study traced back into this repository. |
| R1021-27 | Give every requirement a traceability row. | The rows above and their entries in `docs/requirements-traceability.md`, honest "not yet confirmed" included. |
| R1021-28 | A CI failure caused by a transient upstream stall is survived, not merely reported. | `scripts/apt-install-with-retry.sh` bounds each attempt inside the step budget issue #1017 added, kills a stalled attempt while the budget still has room for another, and refuses to start when its attempts cannot fit -- so a hung package mirror can no longer fail a pull request that did not cause it. See finding 14. |
| R1021-29 | A test that reports a process was terminated distinguishes termination from a write that has not happened yet. | `timeout_terminates_descendant_processes` asked the filesystem a question the filesystem cannot answer: `descendant-survived` is absent both when the descendant died and when it is alive but still sleeping, so on a loaded macOS runner the old 150 ms proof-of-life lost its race with the kill (run 32272689475, job 96137354605). The fixture now records the descendant's pid and the test polls the kernel for it, naming each failure separately: never spawned, still running, or finished before the kill arrived. Verified by mutation -- a descendant moved into its own process group is reported as still running. See finding 15. |
| R1021-30 | A deadline a CI script depends on exists on every runner the tests run on. | `scripts/apt-install-with-retry.sh` bounded its attempts with GNU `timeout`, which macOS does not ship, so the macOS core slices failed the tests that drive it while the Linux job it ships in was green (run 32282461075, jobs 96170638546 and 96170638704). `scripts/run-with-deadline.sh` is one deadline for both families, keeping `timeout`'s 124-on-expiry contract, and `no_committed_script_reaches_for_a_timeout_binary_macos_does_not_have` holds the rule for every tracked script and workflow rather than for the line that was caught. Writing the deadline means owning its accuracy too: it is never early, which `the_deadline_never_expires_before_the_time_it_was_given` pins after the first draft expired a 3s deadline in 2.6s. Both families now run it: every `ci_cd::issue_1021` test is green on the macOS core slices of run 32294252392. See findings 16, 17 and 18. |
