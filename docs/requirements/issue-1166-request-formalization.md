## Issue #1166 The Request Formalized into Obligations

Issue [#1166](https://github.com/link-assistant/formal-ai/issues/1166) (E131)
replaces phrase matching with request formalization: an issue body parses
into an obligation graph whose nodes carry semantic kinds and anchored
literals, mentions of the same quoted literal collapse to one node (the
structural fix for the Kotlin doubled output of #1156), and nothing
underivable is silently discarded. The root-cause analysis lives in
`docs/case-studies/issue-1166/`.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1166-1 | An issue body parses into an `ObligationGraph`; every enumerated requirement produces an `ObligationNode` anchored to seed meanings/roles. | Implemented: `rust/src/intent_formalization/obligations.rs` (`formalize_request`) builds on `obligation_ledger::ObligationNode::build` — no new ledger type — and classifies clauses against `print_stdout`, `ci_workflow_request`, and the program-request roles. Pinned by `rust/tests/unit/issue_1166_obligation_routing.rs`. |
| R1166-2 | Two or more mentions of the same quoted literal produce exactly one output-literal node. | Implemented: `coreference_pass` merges by literal value across clauses; `two_identical_output_clauses_produce_one_node` proves three mentions (intro, "print exactly", Expected Output) yield one node and one value. JavaScript root (2026-10-07): `coreferencePass` and the new `uniqueOutputLiteral`/`literalFor` in `js/agentic/crate/intent_formalization_obligations.mjs` hold the same cases. Pinned by `rust/tests/unit/issue_1166_obligation_routing.rs` and `rust/tests/web/issue-1166-obligation-routing.test.mjs`. |
| R1166-3 | The executor derives its plan from obligation nodes and reports undischargeable nodes with byte spans. | Implemented 2026-10-07 (this pull request; the JS root verified locally, the Rust root awaiting CI). The graph exposes `obligations_of_kind` and `gap_report` (node id + byte span + reason). The executor's CI-workflow decision comes from the graph: `ci_workflow::requested_in` delegates to `intent_formalization::request_demands(objective, ObligationKind::CiWorkflow)`, and its JS twin `requestedIn` (`js/agentic/ci_workflow.mjs`) reads the same clause nodes (`ci_workflow_demand_is_read_from_the_obligation_graph`, Rust and JS). The program executor's output operands come from the graph too: `program_contract::explicit_stdout` and its JS twin `explicitStdout` read `intent_formalization::bound_output_literals` (`js/agentic/crate/intent_formalization_obligations.mjs` `boundOutputLiterals`), which assigns every quoted segment to the enumerated obligation clause (`clauses_with_spans`) that contains it and binds it when its introduction inside that clause evidences the seed `print_stdout` meaning, each value once. The routing change this makes, pinned in both roots: a print verb in an earlier enumerated clause no longer binds a literal in a later one (`Print the greeting! Then "Hello"` binds nothing; the old reading bound `Hello` because `!` was not one of its breaks); every other shape binds as before. The graph's broader `OutputLiteral` classification is kept for reporting rather than binding, so it cannot widen which prompts get a program contract; a literal it demands that the binding does not carry is reported (R1166-4). The clause vocabularies (output verbs, code style, file naming, CI badge) moved out of code into the seed roles `output_obligation_verb`, `code_style_obligation`, `file_naming_obligation` and `ci_badge_obligation` (`data/seed/meanings-repository-workflow.lino`), which the JS port reads too. The JS ledger's `opensAClause` now reads a line break before trimming, as the Rust `opens_a_clause` has since #1166, so both roots enumerate the same clauses. Pinned by the shared fixture `rust/tests/fixtures/issue-1166/executor-gaps.json` (`rust/tests/unit/issue_1166_executor_gaps.rs`, `rust/tests/web/issue-1166-executor-gaps.test.mjs`) and `rust/tests/unit/issue_1166_obligation_routing.rs`. The parity corpus `data/parity/cross-runtime-synthesis.json` has no program-contract case and the browser runtime is the Rust worker, so the Rust/JS twin parity for this routing lives in that shared fixture instead. |
| R1166-4 | A completed run emits an obligation report for each undischargeable node; none is silently omitted. | Implemented 2026-10-07 (this pull request; the JS root verified locally, the Rust root awaiting CI). `intent_formalization::obligation_gap_lines` is the report: the `gap_report` lines (clauses no rule can read) followed by `ObligationGraph::unbound_output_report` (output literals the graph demands that the executor's binding does not carry, under the `output_literal_not_bound_by_executor` reason of the `unbound_output_literal` rule in `data/meta/obligation-evidence-contract.lino`), so a demanded value the program would not print is no longer omitted silently. `record_obligation_gaps` writes each line as an `obligation_gap` event from every executor that reads the graph: the program-contract executor (`coding::program_contract::answer`, used by the solver and the agentic planner) and the catalog `write_program` executor in `rust/src/solver.rs` whenever the request formalizes into work obligations or demands the CI workflow the agentic work-item executor attaches. The JS agentic root keeps no event log, so its executor `programContractAnswer` (used by `js/agentic/planner.mjs` and `js/agentic/general_execution.mjs`) carries the same lines as `obligation_gaps`; the catalog `write_program` arm is native-only there (documented in `general_execution.mjs`), so that emission has no JS twin. The browser worker (`js/worker/`) records the same events (2026-10-07, verified locally): its catalog `WriteProgram` tail (`solverWriteProgramEvents`, `js/worker/formal_ai_worker_solver_events.js`) appends `solverObligationGapEvents` between `legacy_intent` and `procedure_cache`, where the native branch records them, behind the same gate. The port is `js/worker/formal_ai_worker_obligations.js` (clause enumeration, the clause-level ledger tree with its one-level checkable split, `derive_expectation`, the seed-role classifier, coreference, `bound_output_literals`, `obligation_gap_lines`) and `js/worker/formal_ai_worker_obligation_plans.js` (the general-planner mode `derive_expectation` consults, never the plan itself). Its vocabulary is the seed lexicon; the two `data/meta` decisions the worker cannot fetch (the expectation rules of `obligation-evidence-contract.lino` and the approved `missing_operation_contract` strategy of `task-decomposition-strategies.lino`) are mirrored in the worker and held equal to the files by its test. The fixture's `catalogCases` pin six catalog requests, five carrying work or CI obligations (one with an unbound output literal) and one carrying none, in the worker (`rust/tests/web/issue-1166-worker-obligation-gaps.test.mjs`: exact events, order and position; it also holds the worker's lines, plan modes and checkable splits equal to the agentic root on every fixture prompt and fourteen plan-shaped prompts) and in the native solver (`catalog_requests_record_the_worker_gap_lines` in `rust/tests/unit/issue_1166_executor_gaps.rs`, awaiting CI; it checks the exact lines and their presence in the run's Links Notation, not their order there). Still open: the worker port is a hand mirror, not the Rust-to-WASM path the worker line budget asks for, so it must be kept in step with the Rust module by these tests. Pinned by `rust/tests/unit/issue_1166_executor_gaps.rs`, `rust/tests/web/issue-1166-executor-gaps.test.mjs` and `rust/tests/web/issue-1166-worker-obligation-gaps.test.mjs`, which assert the same fixture lines (node ids, spans, reasons) in the native, agentic and worker roots. |
