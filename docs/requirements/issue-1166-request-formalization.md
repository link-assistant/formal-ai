## Issue #1166 The Request Formalized into Obligations

Issue [#1166](https://github.com/link-assistant/formal-ai/issues/1166) (E131)
replaces phrase matching with request formalization: an issue body parses
into an obligation graph whose nodes carry semantic kinds and anchored
literals, mentions of the same quoted literal collapse to one node (the
structural fix for the Kotlin doubled output of #1156), and nothing
underivable is silently discarded. The root-cause analysis lives in
`docs/case-studies/issue-1166/`.

| R1166-3 | The executor derives its plan from obligation nodes and reports undischargeable nodes with byte spans. | Implemented 2026-10-07 (this pull request; the JS root verified locally, the Rust root awaiting CI). The graph exposes `obligations_of_kind` and `gap_report` (node id + byte span + reason). The executor's CI-workflow decision comes from the graph: `ci_workflow::requested_in` delegates to `intent_formalization::request_demands(objective, ObligationKind::CiWorkflow)`, and its JS twin `requestedIn` (`js/agentic/ci_workflow.mjs`) reads the same clause nodes (`ci_workflow_demand_is_read_from_the_obligation_graph`, Rust and JS). The program executor's output operands come from the graph too: `program_contract::explicit_stdout` and its JS twin `explicitStdout` read `intent_formalization::bound_output_literals` (`js/agentic/crate/intent_formalization_obligations.mjs` `boundOutputLiterals`), which assigns every quoted segment to the enumerated obligation clause (`clauses_with_spans`) that contains it and binds it when its introduction inside that clause evidences the seed `print_stdout` meaning, each value once. The routing change this makes, pinned in both roots: a print verb in an earlier enumerated clause no longer binds a literal in a later one (`Print the greeting! Then "Hello"` binds nothing; the old reading bound `Hello` because `!` was not one of its breaks); every other shape binds as before. The graph's broader `OutputLiteral` classification is kept for reporting rather than binding, so it cannot widen which prompts get a program contract; a literal it demands that the binding does not carry is reported (R1166-4). The clause vocabularies (output verbs, code style, file naming, CI badge) moved out of code into the seed roles `output_obligation_verb`, `code_style_obligation`, `file_naming_obligation` and `ci_badge_obligation` (`data/seed/meanings-repository-workflow.lino`), which the JS port reads too. The JS ledger's `opensAClause` now reads a line break before trimming, as the Rust `opens_a_clause` has since #1166, so both roots enumerate the same clauses. Pinned by the shared fixture `rust/tests/fixtures/issue-1166/executor-gaps.json` (`rust/tests/unit/issue_1166_executor_gaps.rs`, `rust/tests/web/issue-1166-executor-gaps.test.mjs`) and `rust/tests/unit/issue_1166_obligation_routing.rs`. | R1166-10 | Reversed comparisons, `and`/`or` and negated conditions stay distinct. | Implemented 2026-11-16 (this pull request). `task_condition` (`rust/src/agentic_coding/task_condition.rs`, JS `js/agentic/task_condition.mjs`) reads a conditional output statement into a condition over seed relation, connective, negation and marker roles, then evaluates it into a truth table (inputs in code-point order, values 0..2). The canonical meaning is the table, so `x > y`, `y < x` and `x is greater than y` share one meaning while `x < y`, `and` vs `or` and `unless`/`not less than` differ. | R1166-11 | Mandatory comments, run instructions and workflow clauses cannot be omitted while the task is reported complete. | Implemented 2026-11-16 (this pull request). `task_acceptance::check_task` gives every clause a verdict; the report is `complete` only when no clause is contradicted or unresolved.
