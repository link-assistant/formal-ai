## Issue #982 Persisted-Memory Compatibility Contract

Issue [#982](https://github.com/link-assistant/formal-ai/issues/982) requires a
safe upgrade boundary for long-lived `.lino` memory shared by CLI, server,
desktop, Telegram, and container deployments. The schema contract lives in
`rust/src/memory/upgrade.rs`; operator guidance is in
`docs/configuration/memory.md`; regression and container coverage is in
`rust/tests/integration/issue_982_memory_upgrade.rs` and
`experiments/issue_982_memory_upgrade/run_container_upgrade.sh`.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R982-1 | Preflight compatibility must be machine-readable and must not mutate memory or create migration artifacts. | Implemented by `formal-ai memory upgrade-status --format json` / `preflight_memory_upgrade`; `upgrade_status_detects_released_schema_without_mutating_memory` asserts byte equality and a one-entry directory. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs`. |
| R982-2 | Persist and report explicit detected, minimum-readable, maximum-readable, and target schema versions. | Implemented: schema 1 names released unversioned `demo_memory`; schema 2 adds the root marker. `formal-ai memory upgrade-status --format json` and `/health` (Rust, and the JavaScript server's `memoryHealthStatus`) expose the detected, minimum-readable, maximum-readable, and target schema versions and the migration state. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs` (`upgrade_status_detects_released_schema_without_mutating_memory`, `health_exposes_schema_compatibility_without_triggering_migration`) and `rust/tests/web/server-memory-schema.test.mjs`. |
| R982-3 | Upgrades must be explicit; startup, health, ordinary reads, and ordinary writes must never silently migrate an existing file. | Implemented: `MemoryStore` and `SyncStore` (and the JavaScript `SyncStore`) retain the detected source schema on save, a new store starts at the target schema, and only `memory migrate` moves an existing file to schema 2. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs` (`ordinary_server_write_preserves_released_schema_and_unknown_metadata`, `first_write_to_a_new_store_uses_the_target_schema`, `health_exposes_schema_compatibility_without_triggering_migration`) and `rust/tests/web/server-memory-schema.test.mjs`. |
| R982-4 | Migration must coordinate with ordinary writers and reject incompatible/future schemas without modifying them. | Implemented: `migrate_memory` holds the sibling `fs2` writer lock for the whole transaction and fails closed; a held lock, a future schema (99), and malformed memory each return a nonzero JSON refusal and leave the file byte-identical, and both servers refuse ordinary writes to an incompatible file. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs` (`live_writer_lock_causes_machine_readable_refusal_without_modification`, `future_schema_is_refused_nonzero_and_never_modified`, `malformed_memory_is_refused_nonzero_and_never_modified`) and `rust/tests/web/server-memory-schema.test.mjs`. |
| R982-5 | Create and verify a byte-exact rollback backup before commit. | Implemented: the migration writes the backup, re-reads it, and checks both bytes and SHA-256 before staging; it preserves source permissions, refuses a pre-existing backup holding other bytes (`backup_conflict`, both files untouched), and records the backup path and both digests in the receipt. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs` (`migration_is_atomic_lossless_receipted_idempotent_and_rollback_safe`, `conflicting_backup_is_refused_and_the_default_backup_is_content_addressed`). |
| R982-6 | Commit atomically and make interruption/retry safe and idempotent. | Implemented: same-directory create-new staging, `sync_all`, atomic rename, parent sync, cleanup on the pre-commit interruption hook, a default backup named by the source digest (a retry re-verifies the same file), and a target-schema no-op retry. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs` (`interrupted_migration_keeps_original_byte_identical_and_retryable`, `migration_is_atomic_lossless_receipted_idempotent_and_rollback_safe`, `conflicting_backup_is_refused_and_the_default_backup_is_content_addressed`). |
| R982-7 | Preserve unknown metadata, stable identifiers, event ordering, and history. | Implemented: migration inserts only the additive root marker, and event parsing/formatting round-trips unknown fields in both runtimes. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs` (the whole-flow case compares exact bytes apart from the marker and checks ids, order, extensions, query, and export; `released_writer_escapes_are_valid_upgrade_input_and_round_trip_losslessly`) and `rust/tests/web/server-memory-schema.test.mjs`. |
| R982-8 | Emit a durable machine-readable migration receipt with rollback instructions. | Implemented: `MemoryMigrationReceipt` carries binary and schema versions, migration id, memory/backup/receipt paths, before/after SHA-256, event count, changed flag, and rollback strategy; it is written durably beside the memory (or to `--receipt`) and printed on stdout. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs`: the receipt equals its exact expected value, the file equals stdout, and a no-op retry reports `not_required`. |
| R982-9 | Provide fixtures for every readable/released schema and reject an intentionally incompatible fixture. | Implemented: `rust/tests/fixtures/memory/schema-{1,2}.lino` cover every readable schema and are enumerated by `fixtures_cover_every_readable_schema` and by the JavaScript twin, which also asserts no other schema fixture exists; the schema-99 case verifies status and migration refusals. Pinned by `rust/tests/integration/issue_982_memory_upgrade.rs` and `rust/tests/web/server-memory-schema.test.mjs`. |
| R982-10 | Prove a previous released container and candidate container can use the same named volume through upgrade, verification, rollback, and old-version reopen. | Implemented by `experiments/issue_982_memory_upgrade/run_container_upgrade.sh`, which `.github/workflows/release.yml` runs after building the candidate image: it writes with the released `0.335.0` image, preflights and migrates with the candidate, checks candidate query/export and server `/health`, restores the verified backup, and reopens it with `0.335.0`. The two-image run needs Docker and the published image, so it executes in CI; `rust/tests/integration/issue_982_memory_upgrade.rs` (`container_upgrade_harness_runs_in_ci_from_released_write_to_released_reopen`) pins the wiring and the stage order, and `rust/tests/unit/ci-cd/issue_1069.rs` its container cleanup. |
| R982-11 | Keep implementation provenance and self-hosting evidence reproducible. | Implemented: the issue/PR evidence collector outputs are committed with a manifest under `docs/case-studies/issue-982/raw-data/github/`; two differently worded real Agent-CLI runs and deterministic session JSON live under `docs/case-studies/issue-982/self-hosting/` and are replayed byte-for-byte by `rust/tests/integration/issue_982_self_hosting.rs`. |
