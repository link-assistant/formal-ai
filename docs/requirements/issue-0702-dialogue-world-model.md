## Issue #702 Dialogue World Model

Issue [#702](https://github.com/link-assistant/formal-ai/issues/702) (E60, child
of [#651](https://github.com/link-assistant/formal-ai/issues/651)) implements the
per-requirement plans issue #649 drafted: PR
[#675](https://github.com/link-assistant/formal-ai/pull/675) landed the
substrate (`src/world_model.rs`), but nothing fed it from a conversation. PR
[#818](https://github.com/link-assistant/formal-ai/pull/818) adds the dialogue
layer — utterance classification from cue data, a `DialogueWorldModel` that
maintains current/target contexts with provenance and a hash-chained
synchronization log, a chat handler that answers "what is left to do?" from the
current→target difference in all four languages, and a bAbI-style state-tracking
benchmark slice with a ratchet. It also provides one unlimited, explicitly
inherited context hierarchy for dialogue turns, tasks, pull requests, issues,
repositories, and organizations, with lazy nearest-first reference resolution.
The whole feature is **trace-only until opted in**:
`SolverConfig::world_model_mode` defaults to `Off`. The case study lives in
`docs/case-studies/issue-702`.

| ID | Requirement | Status |
| --- | --- | --- |
| R702-1 | Seed and maintain the current-state context from the dialogue, with provenance back to the turn that asserted each fact. | Implemented by `DialogueWorldModel::from_turns`/`observe` and `record_provenance` in `src/world_model_dialog.rs`; every asserted atom carries `asserts:<atom>` and `provenance:turn:<n>`. Covered by `declarative_turns_seed_the_current_state_context_with_provenance`. |
| R702-2 | Build the target-state context from intent formalization: "I want …" statements and imperative requests. | Implemented by `world_model_atoms::classify` over the `world_state_target` cue set in `data/meta/cue-lexicon.lino` (en/ru/hi/zh, no Rust phrase tables) plus `state_atom` extraction. Covered by `wishes_and_requests_build_the_target_state_context` and `all_four_languages_route_the_same_three_utterances_the_same_way`. |
| R702-3 | Expose `diff(current, target)` as a links network, queryable from chat. | Implemented by `DialogueWorldModel::difference`/`remaining` and the `world_state` contextual handler in `src/solver_handlers/world_state.rs`, which answers `world_state_remaining` / `world_state_reached` and emits `world_state:remaining`, `world_state:difference`, `world_state:sync_events` evidence links. | R702-4 | Run a synchronization loop where the agent proposes, the user confirms or corrects, and every step is an append-only event. | Implemented by `propose_target` plus confirmation/correction routing in `observe`, recorded as `SyncEvent`s whose `derived_id` hashes the previous event. Covered by `the_agent_proposes_the_user_confirms_and_both_converge`, `a_correction_replaces_the_proposal_and_supersedes_the_old_target`, and `the_synchronization_log_is_append_only_and_hash_chained`. |
| R702-5 | Treat merge and split as first-class operations: union with conflict detection, split by topic/subtree. | Implemented by `merge_from` (returns the conflicting links instead of silently picking a winner) and `split_current` over `Context::split_off`. Covered by `contexts_merge_with_conflict_detection_and_split_round_trips`. |
| R702-6 | Make statements dependent through relative-meta-logic so a change recalculates dependents, with a trace naming each recalculated link. | Implemented by `depends_on` and `revise_statement`, which return a `RecalculationReport` naming every touched statement over the RML decimal truth grid. Covered by `revising_a_premise_recalculates_every_dependent_statement`. |
| R702-7 | Predict action consequences: `predict(current, action) -> hypothetical_state` compared with the target, reporting satisfied and violated needs, deterministically and inspectably. | Implemented by `DialogueWorldModel::forecast` returning `ActionForecast { satisfied, violated, remaining_before, remaining_after }` as Links Notation, with `violates_target()` flagging destructive actions before execution. Covered by `a_helpful_action_shrinks_the_gap_and_a_destructive_one_is_flagged`. |
| R702-8 | Keep everything links (no embeddings, no graph/edge/vertex terms), support all four languages, put the knobs in `SolverConfig`, and stay trace-only until opted in. | Implemented by `WorldModelMode::{Off, Track}` in `SolverConfig::world_model_mode` (env override `FORMAL_AI_WORLD_MODEL_MODE`), Links Notation artifacts, and data-driven cue sets. Covered by `the_world_model_mode_is_off_until_it_is_opted_in`, `the_world_model_handler_is_inert_until_the_knob_is_opted_in`, `the_whole_dialogue_model_renders_as_links_notation`, and `the_answer_is_recomputed_from_the_dialogue_and_never_mentions_embeddings`. |
| R702-9 | Acceptance: a scripted multi-turn dialogue, a premise change with its trace, a prediction that shrinks the diff and flags a destructive action, merge/split round-trips, and a bAbI-style state-tracking benchmark slice with a ratchet. | Implemented by `a_scripted_dialogue_tracks_state_answers_the_goal_question_and_forecasts` plus `data/benchmarks/world-state-tracking-suite.lino` (16 dialogues, en/ru/hi/zh, held-out paraphrases) with the ratchet test `issue_702_world_state_suite_tracks_each_case` (`minimum_pass_count` 16), catalogued in `docs/benchmarks.md`. |
| R702-10 | Collect the issue data and the analysis under `docs/case-studies/issue-702/`. | Implemented by `docs/case-studies/issue-702/{README.md,requirements.md,solution-plans.md,raw-data/}` and protected by `tests/unit/docs_requirements_issue_702.rs`. |
| R702-11 | Support unlimited nested contexts for conversation, dialogue, task, pull request, issue, repository, organization, and future scopes. | `ContextHierarchy` in `src/world_model_context.rs` stores named `Context`s and iterative child→parent declarations with cycle rejection and no depth constant. Covered at 320 levels by `reference_resolution_has_no_fixed_context_depth_limit_and_is_lazy`. |
| R702-12 | Make inheritance explicit: full, fully isolated, or partial and conditional for any link-carried axiom, fact, requirement, or goal. | `InheritancePolicy::{Full, Isolated, Conditional(Vec<LinkPattern>)}` applies conditions cumulatively at every crossed boundary. | R702-13 | Resolve references lazily from the closest context outward, stop at the nearest exact match, and reach the outside world only when explicitly allowed. | `ContextHierarchy::resolve` returns a `ReferenceResolution` with ordered `visited` contexts, nearest context/depth, matched links, and `Unresolved` versus `ExternalLookupRequired`; it performs no network action. Covered by `dialogue_turns_are_real_nested_contexts_not_only_a_standalone_utility`, `runtime_coreference_searches_nearest_relevant_ancestor_turn`, issue-687 research tests, and the Rust/browser parity guard. |
