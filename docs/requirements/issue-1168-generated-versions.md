## Issue #1168 Generated Code Uses Versions Resolved at Generation Time

Issue [#1168](https://github.com/link-assistant/formal-ai/issues/1168) (E133)
makes every third-party version a generated artifact pins — action refs,
toolchain versions, the Java LTS — a *resolved* value with provenance, never a
memorized string. Resolution happens at generation time from the publisher's
own API, is recorded in the derivation, and degrades loudly (cache, then
shipped baseline, each said out loud) rather than silently going stale.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1168-1 | The latest release tag and its commit SHA for every third-party GitHub Action in a generated CI workflow are fetched from `https://api.github.com/repos/{publisher}/{repo}/releases/latest` (then `commits/{tag}` for the SHA). | Implemented: `resolve_github` in `rust/src/version_resolution.rs`, covering `actions/checkout`, `actions/setup-java`, `fwilhe2/setup-kotlin`, `actions/setup-python`; pinned by mocked-transport tests (`resolves_every_pin_from_live_fixtures`). Generation-time path (2026-10-07): `VersionSet::for_generation` now opens its `CachedSourceClient` online when `FORMAL_AI_LIVE_FETCH` is set (the repository's live-retrieval opt-in); before, it was always offline, so a generated workflow never read a publisher's API. The JavaScript root has the same ladder: `js/agentic/crate/source_cache.mjs` mirrors `CachedSourceClient::fetch` over an injected io in the native cache layout, and `forGeneration()` reads the installed host's `sourceFetch` (`js/agentic/node-host.mjs`: `FORMAL_AI_SOURCE_CACHE_DIR`, curl under `FORMAL_AI_LIVE_FETCH`). Pinned by `rust/tests/unit/issue_1168_latest_versions.rs` and `rust/tests/web/issue-1168-source-cache.test.mjs`. |

| R1168-8 | Three-roots parity: `version_resolution.rs` translated to js/ts and parity cases added. | Implemented (2026-10-07, this pull request; JavaScript verified locally, Rust awaiting CI). JS root: `js/agentic/crate/version_resolution.mjs` mirrors `VersionSet::resolve` (`resolveVersionSet`, over an injected `fetch` that stands in for `CachedSourceClient`, with the same live → cache → baseline ladder and capture order), `VersionSet::record` (`recordVersionSet`), the coursier/Scala pins, and `VersionSet::for_generation` (`forGeneration(fetch)`, the shipped baseline when the host passes no fetch); `rust/tests/web/issue-1168-version-resolution-parity.test.mjs` reproduces the Rust unit cases (6 tests). Parity over the generated pins: the agentic planner's workflow render now takes its version source by injection in both runtimes -- Rust `ci_workflow::render_with(recipe, versions)` (re-exported as `formal_ai::agentic_coding::render_ci_workflow`) and JS `renderWith(recipe, versions)` in `js/agentic/ci_workflow.mjs`; `render` injects the generation-time set. Correction to the earlier re-check: `VersionSet::for_generation` never reaches the network -- `CachedSourceClient::new` builds the client with `online: false`, so the native ladder is cache → baseline, and with no source cache it is the baseline, as `forGeneration()` is in JS. `rust/tests/fixtures/issue-1168/workflow-render-parity.json` pins the full workflow text the planner attaches for the Kotlin, Python, Scala and Rust program-contract prompts, rendered from the offline shipped baseline; `rust/tests/unit/issue_1168_workflow_render_parity.rs` (via `program_contract::answer` and `render_ci_workflow`) and `rust/tests/web/issue-1168-workflow-render-parity.test.mjs` (via `programContractAnswer` and `renderWith`, 2 tests passing locally) assert the same text. Since 2026-10-07 the Node host owns the source cache too (`js/agentic/crate/source_cache.mjs`, R1168-1), so JavaScript generation replays the same `FORMAL_AI_SOURCE_CACHE_DIR` captures the native host does; only the browser host, which reads no files, answers from the baseline. |
