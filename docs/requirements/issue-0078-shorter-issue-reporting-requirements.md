## Issue #78 Shorter Issue Reporting Requirements

Issue [#78](https://github.com/link-assistant/formal-ai/issues/78) reports
that the prefilled `Report issue` URL overflows GitHub's 8192-byte
`/issues/new?body=…` limit (mobile shows *"Whoops, something went wrong!"*,
desktop shows *"Whoa there! Your request URL is too long."*). The
requirements below shrink the prefilled body until it fits, by moving the
long memory-upload instructions into a single docs page and by recording
the dialog as a compact `U:` / `A:` code block.

| ID | Requirement | Status |
| --- | --- | --- |
| R115 | The prefilled `Report issue` body must keep the encoded `body=` query parameter under GitHub's request-line limit so the new-issue page actually opens for typical sessions (no more *"URL is too long"*). | Implemented by collapsing the three-paragraph **Attach full memory** block into one sentence + docs link, and by rendering the dialog as a single fenced code block instead of a per-message subsection loop. `createIssueReportBody` in `src/web/app/main.jsx` gathers the facts and `renderReportBody` (`src/web/app/issue-report.js`) emits them; `fitIssueUrl` still drops earlier turns until the encoded URL fits. The compact form is exercised by `experiments/issue-78-dialog-format.mjs` and asserted by the e2e tests below. |
| R116 | The dialog transcript embedded in the prefilled body must use a single fenced code block with `U:` / `A:` line prefixes, instead of one Markdown subsection per message, while still preserving the focused-message marker and the assistant `intent` annotation when the assistant could not classify the prompt. | Implemented by the **Reproduction of dialog** section of the shared builder (`src/issue_report.rs`, mirrored by `src/web/app/issue-report.js`), which also picks a fence long enough to contain the dialog. The block opens with `issue_report_dialog_legend` from `data/seed/agent-info.lino` — `Legend: \`U\` = user, \`A\` = agent, \`T\` = tool result.` since #839 gave the agentic surface tool results to report; known-intent turns stay as plain `A: …` to match the issue example, and the focused-message marker plus the `intent` annotation only appear inline for the `unknown` intent (`A (intent: unknown, reported): …`) where they actually carry diagnostic value. Covered by the `known assistant dialogs include a prefilled issue report link` and `unknown prompts include a prefilled missing-rule issue link` tests in `tests/e2e/tests/demo.spec.js`. |
| R117 | The verbose upload-memory instructions (Gist / `.zip` / per-OS walkthroughs / redaction reminders) must live in a single page checked into the repository so the prefilled body only needs a one-line pointer with a link. | Implemented by [`docs/upload-memory.md`](../upload-memory.md) and the matching link in the **Attach full memory (optional)** section the shared builder emits. The topbar `Report issue` and `Export memory` tooltips also point at the same doc instead of repeating the workflow. |
| R118 | Documentation must explain that users can either upload the full memory export to a GitHub Gist (no extension restrictions) or wrap it in a `.zip` (GitHub's issue uploader still rejects raw `.lino`). | Implemented by the *Step 3 — Attach the file (choose one)* section of `docs/upload-memory.md`, which documents both Option A (Gist) and Option B (`.zip`) and links the GitHub attachment-types doc as the upstream constraint. |
| R119 | The e2e regression suite must enforce all of the above: the prefilled body must contain `docs/upload-memory.md`, the dialog must use the seeded `Legend: …` block, and the old verbose per-OS Compress / Send-to instructions must be absent. | Implemented by extending `Report issue link is present in the topbar and links to the upload-memory guide (R112 + issue #78)` in `tests/e2e/tests/multilingual.spec.js` (asserts `docs/upload-memory.md` and forbids the per-OS Compress / Send-to phrases) and by tightening the prefilled-body assertions in `tests/e2e/tests/demo.spec.js`. |
