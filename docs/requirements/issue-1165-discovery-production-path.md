## Issue #1165 Discovery on the Production Path

Issue [#1165](https://github.com/link-assistant/formal-ai/issues/1165) (E130)
puts the coding-by-discovery machinery on the path users and Hive Mind hit:
every stored program becomes a *cache entry* that names where a rediscovery
starts from, a cache miss routes to `research_coding_skill_gap` instead of a
template literal, and the whole cache is deletable by design. The analysis
and the wiring plan live in `docs/case-studies/issue-1165/`.

Third pass (2026-10-07): the discovery a miss would run now exists outside this module: the #1164 decomposer recomposes a Hello World program from the real captures under `rust/tests/fixtures/coding-discovery/captured/` (Rust Book, go.dev, kotlinlang, Scala book, Swift book). Running it over those captures in the browser engine (the case-study procedure) shows why it is not yet wired in as the answer: the page formalizer strips each code line's leading whitespace in both roots (`strip_tags_keep_lines`, `rust/src/web_formalize.rs`, and `pageStripTagsKeepLines`, `js/worker/formal_ai_worker_web_formalize.js`, both apply the per-line tag stripper to `<pre>` text), so every recomposed program comes back unindented (`fn main() {\nprintln!(...);\n}`). Answering from it would regress the programs users get, and the fix belongs to the formalizer (#1163). Separately, the captures are test fixtures, not shipped source data, so an offline production solve has nothing to rediscover from. |
