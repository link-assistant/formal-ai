## Issue #1184 White-Box Derivation for Every Answer

Issue [#1184](https://github.com/link-assistant/formal-ai/issues/1184) (E148)
requires the meta algorithm to be white box: every answer carries its
derivation — search queries, fetched URLs with hashes, formalized fragments,
decomposed parts, the recomposition, the rendering, the verification — as a
durable record keyed by a content-addressed `derivation_id`, and
`formal-ai explain <answer-id>` prints it afterwards. The audit of what
`EventLog`, `SourceCapture`, and `VerifiedAnswer` already provide, the plan,
and the delivery survey live in `docs/case-studies/issue-1184/`.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1184-1 | Every `SymbolicAnswer` the solver returns carries a `derivation_id`, content-addressed the way `VerifiedAnswer::derivation_id` is, surfaced on every calling surface. | `SymbolicAnswer::derivation_id` computes `stable_id("answer", &answer)` from the current answer text. Its custom `Serialize` implementation includes the computed id in every JSON response without storing a redundant mutable field; `UniversalSolver` finalizes all of its return paths with a derivation link. The stable id shape and solver serialization are pinned by `every_symbolic_answer_carries_a_stable_derivation_id` and `solver_early_returns_expose_serialized_id_and_live_record`. |
| R1184-2 | A `Derivation` record per answer captures search queries, fetches with SHA-256 and timestamps, formalized fragments, decomposed parts, recomposition, rendering, and verification evidence. | Implemented: `Derivation::record_for(log, answer_id)` projects `EventLog::events()` — `web_search:request` and both `source:http` payload spellings today; `formalize:fragment`, `decompose:part`, `recompose:bind`, `render:emit`, `verify:evidence` are named public constants the E128/E129/E131/E132 landings append. Pinned by `derivation_carries_search_queries_fetches_and_hashes_for_an_online_answer`. |
| R1184-3 | The record is durable and queryable after the answer is returned, keyed by `derivation_id`, without replaying the request. | Implemented: `Derivation::persist`/`load` under `data/cache/derivations/<answer_id>.lino` (the `sources-registry` `cache_path` convention), lossless lino round-trip and honest miss pinned by `durable_record_round_trips_by_answer_id`; path-traversing ids are refused. |
| R1184-4 | `formal-ai explain <answer-id>` prints the full derivation from the durable store. | Implemented: the `Explain` subcommand in `rust/src/main.rs` backed by `rust/src/cli_explain.rs` (`--format text` readable, `--format links` the canonical record); the shared miss message names the id shape and the store path. |
| R1184-5 | A stage the route never populated reports "not recorded" — never fabricated or inferred. | Implemented: `explain_text` names every stage and prints `not recorded`; the lino record omits absent stages entirely. Pinned by `explain_reports_not_recorded_for_stages_a_route_did_not_populate`. |
| R1184-6 | The `--thinking` trace and the derivation record are two projections of the same `EventLog`. | Implemented: `record_for` reads `EventLog::events()` and nothing else — the same log `thinking_steps_for_answer` curates. Pinned by `explain_and_thinking_trace_agree_on_the_same_event_log` (the narrated `http_chat` details are exactly the derivation's queries; the derivation additionally keeps fetch hashes the thinking view intentionally drops). |
| R1184-7 | `formal-ai explain` and the self-explanation recipe (`agentic_coding/explain.rs`) keep disjoint triggers. | Implemented and pinned: the subcommand takes a content-addressed id argument and never inspects the running codebase; `explain_command_does_not_collide_with_the_self_explanation_recipe` asserts the recipe's keywords are untouched and an answer id is not one of them. |
| R1184-8 | The Serve API's JSON response includes `derivation_id` alongside `evidence_links`. | The `SymbolicAnswer` serializer emits its current content-derived id alongside `evidence_links`; the solver adds the corresponding derivation id and durable record path to those links. |
| R1184-9 | Three-roots parity: `derivation` module translated to js/ts roots with cross-runtime derivation cases. | Partially delivered. JS root: `js/agentic/crate/derivation.mjs` mirrors every pub item of `rust/src/derivation.rs` (record projection over `{kind, payload}` events in append order, both `source:http` spellings, `VerificationRecord` payload/parse, `to_lino`/`from_lino`, `explain_text`, `answer_derivation_id`, `store_path`, `miss_message`, applied rules read from the schema's `stage ... collects rule` rows of `data/seed/derivation-schema.lino`); `persist`/`load`/`explain_answer` are not mirrored because the JS root has no `data/cache/` write convention. `rust/tests/web/issue-1184-derivation-parity.test.mjs` replays the Rust unit cases and pins byte-identical `to_lino` text. Remaining: the TS root does not mirror `js/agentic` yet, and no `data/parity/cross-runtime-synthesis.json` derivation cases are added. |
