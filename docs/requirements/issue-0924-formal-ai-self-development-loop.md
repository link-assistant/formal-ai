## Issue #924 Formal AI Self-Development Loop

Issue [#924](https://github.com/link-assistant/formal-ai/issues/924) closes E77
by making one real, reviewable Formal AI contribution a release-cycle
condition. The contract, replay evidence, and requirement map live in
[`../case-studies/issue-924/`](../case-studies/issue-924/).

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R924-1 | Require at least one merged Formal AI-authored pull request in each release cycle. | Implemented as a standing, red-until-true floor: `ensure_self_development_release` scans first-parent GitHub merge commits and rejects a release range with no matching session-backed PR. Issue #1085 (D3.5) moved the floor off the release cut onto `.github/workflows/self-development-status.yml` (every push to `main`, every pull request, daily), with no budget, grace period or bypass (issue #1066); every release still records its row. Pinned by `rust/tests/unit/specification/self_hosting_metric.rs` (`release_cycle_requires_a_session_backed_merged_pull_request`, `an_ineligible_cycle_is_blocked_from_the_first_push`, `release_pipeline_and_ledger_remain_pinned_to_the_metric`) and `rust/tests/unit/docs_requirements/self_development_loop.rs` (`issue_924_release_path_enforces_the_loop_before_versioning`). |
| R924-2 | Preserve replayable evidence and prove the authored commit reached review unchanged. | Implemented: the required session/evidence trailers are extended by `Formal-AI-Pull-Request`; the gate matches its number to the merge subject and requires the same commit object in the merged second-parent history, so a trailer on a direct commit or one naming another pull request does not count. Pinned by `rust/tests/unit/specification/self_hosting_metric.rs` (`release_cycle_requires_a_session_backed_merged_pull_request`, `a_committed_evidence_directory_resolves_its_nested_transcripts`) and `rust/tests/unit/specification/self_hosting_metric/authorship_composition.rs` (`release_cycle_rejects_a_commit_claiming_another_pull_request`). |
| R924-3 | Record each contribution and continue reporting per-release and trailing self-hosting share. | Implemented: new ledger rows carry repeated `self_authored_pull_request` values plus the existing changed-line measurements; release notes name the reviewed PR URLs and the target in force. Pinned by `rust/tests/unit/specification/self_hosting_metric.rs` (`release_target_ratchets_and_records_each_self_authored_pull_request`, `recorded_formal_ai_evidence_drives_the_release_metric_and_ratchet`). |
| R924-4 | Make the release target a non-decreasing ratchet, lowerable only in the open. | Implemented: each row records its target. The next target is the greater of the prior target and comparable trailing share, and `ensure_self_development_release` rejects a projection below it while the range can still be repaired; since issue #1085 (D3.5) that check reports from `.github/workflows/self-development-status.yml`, and the release cut records a fall instead of deadlocking on immutable history (issue #812). Because a ratchet that only climbs can strand a cycle it cannot answer (issue #1069), a row may carry a reviewed `target_override_basis_points` that replaces it and carries forward until another commit changes it. That is the only lever: no flag, environment variable, or workflow input moves the target, so every change to the level is a diff and is named in the release notes. Pinned by `rust/tests/unit/specification/self_hosting_metric.rs` (`release_target_ratchets_and_records_each_self_authored_pull_request`, `a_reviewed_override_lowers_the_bar_and_removing_it_restores_the_ratchet`, `a_falling_ratchet_reports_at_release_time_instead_of_blocking_it`) and `rust/tests/unit/specification/self_hosting_metric/ratchet.rs`. |
| R924-5 | Keep E69/E74 dependencies and the ordinary review, CI, and promotion gates intact. | Implemented: E69 supplies the write-effect floor, E74 supplies the two-way Hive Mind gate, and #924 grants no bypass; the Formal AI-authored pull-request contract records `review_ci_promotion "unchanged"`. The real Agent CLI-authored leaf and raw session evidence are committed in the case study. Pinned by `rust/tests/unit/docs_requirements/self_development_loop.rs` (`issue_924_requirements_and_release_contract_are_traceable`, `issue_924_agent_cli_leaf_is_exact_and_replayable`, `issue_924_agent_authored_contracts_are_canonical_and_cover_twenty_percent_of_leaves`). |
| R924-6 | Count a pull request only when every non-merge commit it introduces is validly attributed to Formal AI. | Superseded by the maintainer's decision on [PR #1070](https://github.com/link-assistant/formal-ai/pull/1070#issuecomment-5539328163) (issue #1069): requiring every introduced commit to be attributed measured the composition of a pull request rather than the authorship of the work, so a merged pull request now counts for its attributed part, while an attributed commit naming a different pull request still disqualifies it and unattributed commits stay out of the numerator. The Formal AI-authored `self-development-pull-request-contract.lino` keeps its original wording as immutable evidence. Pinned by `rust/tests/unit/specification/self_hosting_metric/authorship_composition.rs` (`release_cycle_counts_the_attributed_part_of_a_mixed_pull_request`, `release_cycle_rejects_a_commit_claiming_another_pull_request`). |
| R924-7 | Run the same compound task through Formal AI via Agent CLI, attempt it whole first, and split recursively only after observed failure. | Implemented: the issue-924 self-authoring experiment uses incremental dispatch; its committed report retains the failed root, productive three-child split, and passing child sessions. Pinned by `rust/tests/unit/docs_requirements/self_development_loop.rs` (`issue_924_incremental_agent_task_is_replayable_and_learns_from_the_same_sessions`) and `rust/tests/integration/issue_991_incremental_dispatch.rs` (`a_task_too_big_for_the_cli_is_split_from_its_failure_and_composed_back_up`). |
| R924-8 | Compose only verified passing effects and avoid regressing a valid composition with a redundant parent mutation. | Implemented: `TaskExecutor::retry_after_children` lets incremental orchestration verify the parent task directly; the composed-verifier replay and a destructive-parent integration regression pin the behavior. Pinned by `rust/tests/integration/issue_991_incremental_dispatch.rs` (`verified_child_composition_is_not_regressed_by_a_redundant_parent_retry`) and `rust/tests/web/issue-0703-session-replay.test.mjs` (the committed `004-composed-verifier.json` replays with its composition outcome bound to its status). |
| R924-9 | Use those execution sessions for proposal-only auto-learning while leaving promotion human-gated. | Implemented: `learning.lino` observes the four real Agent sessions, excludes the non-client composed verifier, records `human_gated`, and contains no approved decision. Pinned by `rust/tests/unit/docs_requirements/self_development_loop.rs` (`issue_924_incremental_agent_task_is_replayable_and_learns_from_the_same_sessions`). |
| R924-10 | Have Formal AI Agent CLI author at least 20% of the smallest task leaves with exact replay evidence. | Implemented: two of six leaves (33%) are the Agent-authored execution and pull-request contracts; canonical and captured bytes match and native session/resume evidence is retained. Pinned by `rust/tests/unit/docs_requirements/self_development_loop.rs` (`issue_924_agent_authored_contracts_are_canonical_and_cover_twenty_percent_of_leaves`, `issue_924_agent_cli_leaf_is_exact_and_replayable`). |
| R924-11 | Preserve exact reproductions and generalize only from demonstrated failures. | Implemented: focused before/after tests cover mixed PR authorship (since relaxed by R924-6's supersession, with its own before/after pair), cross-platform Python startup, and the redundant parent retry found by the first real incremental run; the case study retains the successful replay. Pinned by `rust/tests/integration/issue_991_incremental_dispatch.rs` (`verified_child_composition_is_not_regressed_by_a_redundant_parent_retry`), `rust/tests/source/source_tests/agent/tests.rs` (`python_commands_have_cross_platform_startup_budget_floor`) and `rust/tests/unit/specification/self_hosting_metric/authorship_composition.rs`. |
