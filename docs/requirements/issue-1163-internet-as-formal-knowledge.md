## Issue #1163 Internet as Formal Knowledge

Issue [#1163](https://github.com/link-assistant/formal-ai/issues/1163) (E128,
part of the #1183 umbrella) turns fetched web pages into formal knowledge: one
generic page formalizer maps any fetched resource to a `LinkNetwork` (headings,
paragraphs, lists, tables, and language-tagged code blocks), search becomes the
entry point for a need no registered source covers, pages carry a data-driven
trust score and a rediscovery record, and queries over formalized pages answer
with links. The issue numbers its requirements 1 to 10; they are
`R1163-1` to `R1163-10` here in the same order. `R1163-11` to `R1163-16` are
the further obligations its "What to build", "How to test", "Design" and
"Definition of done" sections state without a number. The timeline, root
causes and prior art live in `docs/case-studies/issue-1163/`.

The module is `rust/src/web_formalize.rs` (with `rust/src/web_formalize_trust.rs`
included from it), not the `rust/src/page_formalizer.rs` the issue names; the
four test modules the issue sketches are consolidated in
`rust/tests/unit/issue_1163_web_formalize.rs`.

| ID | Requirement | Status / Evidence |

| R1163-1 | A single `formalize_page(bytes, mime_hint) -> LinkNetwork` produces a `LinkNetwork` from any HTML, Markdown, plain-text, JSON, or PDF-text payload. | Implemented: `web_formalize::formalize_page` resolves the mime kind from the hint or the seed's sniff rules (`data/seed/page-formalization-rules.lino`) and builds a `page` root with one `heading` / `paragraph` / `list_item` / `table_row` / `code_block` child per block. Pinned by `html_page_formalizes_structure_and_code`, `markdown_fences_tag_languages_with_unknown_fallback`, `generic_formalizer_covers_bespoke_statements` (JSON) and `plain_and_pdf_text_formalize` in `rust/tests/unit/issue_1163_web_formalize.rs`. The HTML walker once stepped over the whole document (an `<html>` open tag jumped the cursor past `</html>`) and the rule loaders once read no records (they iterated the top level, which holds only the file wrapper); both are fixed on this branch and the HTML test fails if either returns. Note: the network is assembled by inserting links, not by `LinkNetwork::parse`, and bare source files take the plain-text path. |
| R1163-2 | Every code block carries a language tag from the fence annotation, the HTML class, or a heuristic; an unrecognized fence yields `unknown`, never an empty tag. | Implemented: `resolve_language` walks the seed's `tag_source` order (fence, `html_class` with the seed's `language-` and `highlight ` class prefixes, the latter reading GitHub-style `highlight-source-<x>`, shebang and URL-extension heuristic) and falls back to the seed's `unknown`. Pinned by `markdown_fences_tag_languages_with_unknown_fallback` (fences `rust` and `shell`, bare fence `unknown`), `scala_page_tags_language_through_class_prefix` and `html_page_formalizes_structure_and_code` in `rust/tests/unit/issue_1163_web_formalize.rs`. Gap: no test exercises the shebang or URL-extension tier, and an annotated fence the seed does not know (for example a made-up tag) passes through verbatim rather than becoming `unknown`. |
