## Issue #1182: Strict implementation duplication

The target is zero independently maintained duplicate implementation logic in Rust, JavaScript and TypeScript. Tests may repeat cases declaratively. Baselines, body-length thresholds, same-file exclusions, generated headers and historical inventories cannot authorize a clone.

### Implemented guards and canonical projections

The JavaScript/TypeScript guard uses maintained Babel parsing and scope resolution. It visits functions, methods, arrows and nested callables, normalizes only bindings declared within the callable, and preserves literals, properties, captured/global references, operators, effects, async and generator flags. Unparsed sources, missing or orphan projections and invalid custody refuse acceptance. Installed local Babel7.29.7 qualified local controls; package.json and bun.lock now declare Babel8.0.7, whose hosted execution is a separate qualification.

The Rust guard uses Syn AST functions, methods and closures with no body-size or same-file exemption. Opaque item macros require actual expansion custody and remain coverage gaps. Native compilation and all nine native controls remain pending hosted CI; no clean Rust clone count is claimed.

Production inputs are the NUL-safe union of tracked and new nonignored sources. Ignored compiled outputs are not source; tracked generated implementations remain scanned. Reports retain every raw group and site.

Exact maintained ES-to-TS regeneration plus source/output/generator SHA identities and unique AST span/path correspondence establish that two rendered callables share one canonical node. Maintained browser-factory regeneration adds independently checked callable token-tree correspondence. The generated outer factory remains scanned. These verified edges compose transitively; two authored same-body callables remain independent definitions. Forged headers, drift, additional callables and ambiguous mappings refuse admission. Proofs are recomputed from current source and cannot be granted by serialized report fields.

Shared shell quoting and failure-invitation composition now have one JavaScript definition projected through Links IR to actual production Rust and through the maintained ES translator to TypeScript. Existing consumers use direct aliases or reexports; they do not keep forwarding copies. A single declarative corpus exercises exact empty/apostrophe/newline/Unicode behavior. This finite extraction does not eliminate all repository duplication.

### Measured debt and acceptance boundary

The last qualified preintegration source snapshot contains 1,098 source files and 28,768 callables: 10,241 raw groups / 26,240 raw sites, 487 exact ES projection proofs and 56 factory proofs. Canonical identity reduces 1,699 independent candidates to 750; zero source/proof gaps were observed in that snapshot. These are dated, source-bound measurements, not current integrated acceptance. Recompute after every source change.

The older check-duplicate-functions.rs scans only Rust, ignores bodies over22 lines and same-file groups, and accepts a historical baseline. Its passing status does not satisfy this policy. The new strict commands default to nonzero exit for any independent candidate or coverage gap. Hosted scanner qualification runs meaningful controls and publishes explicit debt inventories; a successful inventory job does not establish zero duplication.

Consolidate each remaining independent group through shared implementation/data or an adopted maintained dependency. Fix opaque-macro custody and actual translation gaps rather than suppress candidates. Both integrated guards must observe zero independent candidates and zero gaps before strict acceptance. Structural equality is an audit aid, not a proof that differently written algorithms are semantically independent. Complete debt elimination and full semantic review remain Pending.
