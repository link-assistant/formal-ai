## Issue #468 Agentic-Coding Mode

Issue [#468](https://github.com/link-assistant/formal-ai/issues/468) — title
*"Our system should be able to solve such tasks in agentic mode"* — is reframed by
the maintainer comment: the text-formalization protocol in the issue body (Igor
Martynov's *Formal protocol for translating texts into a knowledge base*, with
«Сказка о рыбаке и рыбке» as the canonical input) is **an example task** the system
should solve from the prompt, and the **core task** is the agentic capability —
*"our Formal AI is able to solve the task in agentic coding mode … call all the
tools from any agentic CLI, understand errors from tools … web fetch and web
search"*. Per the comment the project must also collect the issue data, produce a
deep case study with online research, enumerate every requirement, and propose
per-requirement solution plans surveying existing components. Two constraints bind:
the maintainer's *everything is a link* position means the example task's knowledge
base is emitted directly in Links Notation (the meta-language already in the code
base), not as typed-struct entities/ontologies; and external CLIs (`claude`,
`codex`) are pointed *at* the server, never wired *into* the Formal AI engine. The
work lands in PR [#469](https://github.com/link-assistant/formal-ai/pull/469).
