## Standing Doctrine: The JavaScript Server Has Full Parity With the Rust Server (2026-10-07)

Stated by the project owner while continuing the JavaScript-first work
([the 2026-10-06 architect note](../architect-notes/2026-10-06-javascript-first-full-parity.md),
R997-R1000): JavaScript implements everything Rust does, and that now includes
the HTTP server, with full parity with the Rust server guaranteed by CI/CD.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1013 | A dependency-free Node server (`js/server/`, entry `node js/server/main.mjs --port N`, `npm run serve:js`) serves the whole Rust HTTP surface from the browser worker: probes, `/api/hello`, `/health`, `/v1/models`, `/v1/network` and its deprecated `/v1/graph` alias, `/v1/bundle`, `/v1/links` and LinksQL, memory sync, OpenAI chat completions and Responses (with SSE), Anthropic Messages (with SSE), Gemini and Vertex, MCP, the Telegram webhook, conversation reports, every vendor-prefixed alias, the bearer and MCP-origin rules, CORS and the Rust error shapes; it takes the `formal-ai serve` flags and environment. Its modules hold no natural-language literal: the wording is `data/meta/server-messages.lino`. | Delivered 2026-10-07: `js/server/*.mjs` (each under 1000 lines) hosting the worker through `js/server/worker-host.mjs`, which the web test runtime now re-exports; `scripts/check-js-literals.mjs` holds `server_ceiling 0`; `rust/tests/web/server.test.mjs` probes every manifest route on a socket. |
| R1014 | One route table, `data/meta/server-routes.lino` (method, path or pattern, route id, auth), is the single source of truth for both servers: the JavaScript router reads it, and a Rust test holds the Rust dispatcher to it in both directions. | Delivered 2026-10-07: `js/server/routes.mjs` routes from the manifest; `rust/tests/unit/server_route_manifest.rs` asserts every manifest route is served by `handle_api_request_with_auth`, its `auth` column is the Rust bearer rule, and no method/path pair outside the manifest is served. |
| R1015 | Parity is checked, not asserted: a contract corpus covering every route (streaming, errors, auth failures, unsupported models) is sent to both servers and compared after normalizing volatile values. Protocol-shape differences (status, content type, headers, JSON field names and order, SSE frames) are never allowed; content differences are listed in a ratchet whose count only falls. | Delivered 2026-10-07: `rust/tests/fixtures/server-parity/requests.lino`, `scripts/check-server-parity.mjs`, `data/meta/server-parity-ratchet.lino`; the `server parity` job in `.github/workflows/layered-ci.yml` runs it against the cached release binary. Closed 2026-10-07: the worker records the native solver's event log for every finalized turn (`solverEvents`, `js/worker/formal_ai_worker_solver_events.js`: the impulse/language prelude, the intent-formalization route from the intent table and `data/seed/handler-promotions.lino`, the calculator events with a `link-calculator` lino/step-count mirror, the write-program tail, `finalize_simple` and the meta projection) and `js/server/solver-trace.mjs` ports `EventLog::thinking_steps_for_answer`, so `thinking_steps` and `reasoning` match Rust; memory recall, memory inspection and standing requirements answer from the store ahead of the solver (`js/server/memory-answer.mjs`, `js/server/standing-requirements.mjs`); `learning_trace` and the learn route's rule proposals port `self_improvement.rs` (`js/server/self-improvement.mjs`); the consent-gated auto-free-space pass runs on import (`js/server/storage-policy.mjs`, `dreaming-*.mjs`); `DialogScope` is `withDialogScope`/`currentDialogId`; Telegram executes code through the configured execution box (`js/server/execution-box.mjs`, `telegram-execution.mjs`); floats print as serde_json does (`js/server/json.mjs`). Learned meta-reasoner chunks persist through the log as Rust's `memory_sync.rs` does: opening the store imports every `meta_learned_chunk` event into the worker, and recording an exchange appends the chunks learned since (`js/server/meta-learned.mjs`). Open: the agentic planner (being ported separately); `evidence_links` on the Responses surface and the Telegram `/trace` footer need the full native event log (formalization selection, problem frame, need ledger, reasoning standard...), which the worker does not reproduce, so `responses_*` and `telegram_message` stay in the ratchet; `chat_learning_trace` answers the same program and `learning_trace` but its execution status differs, because the JavaScript server has no native program-verification harness; handler-specific events of routes other than the calculator and write_program, `cue_set` promotion conditions, exact memory queries (`memory_query_language.rs`), and the link-cli `.links` sidecar (a binary doublets projection rebuilt from the `.lino` log) are not mirrored. |
| R1016 | No maintained source, data or document file is larger than 1500 lines (Rust keeps its stricter 1000), or it cannot be maintained. Only files nobody edits by hand are exempt: dependency lock files, verbatim captures of upstream sources, and minified bundles. Generated documents split themselves: the requirements register into an index plus parts, the changelog into recent entries plus archives. | Delivered 2026-10-07: `scripts/check-file-size.rs` measures every maintained text format at 1500 (workflows included, down from 2000); `js/app/main.jsx` became 27 modules, `js/styles.css` seven ordered stylesheets under `js/styles/`, `multilingual.spec.js` four specs, `ARCHITECTURE.md` an overview over `docs/architecture/`, `REQUIREMENTS.md` an index over `docs/requirements/assembled/`, `CHANGELOG.md` recent entries over `docs/changelog/`, and the coding-ladder results one task per line. |
