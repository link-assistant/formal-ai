## Issue #1180 Repository History as Formal Context

Issue [#1180](https://github.com/link-assistant/formal-ai/issues/1180) (E145,
part of the E127 umbrella #1183) asks for the repository's full history —
commits, issues, pull requests, comments, reviews and Actions runs — to be
formalized into records the solver can query, so lineage questions ("which
issue asked for X and which pull request delivered it") have an answer.
R1180-1 through R1180-8 are the issue's own numbered requirements; R1180-9
through R1180-11 are derived from its "What to build", "How to test" and
"Depends on" sections so that nothing the issue asks for goes untracked. The
timeline, root causes and verification live in
`docs/case-studies/issue-1180/`.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1180-1 | A commit importer walks `git log` on the working repository and formalizes each commit's author, committer date, subject, body, trailers (`Refs #NNN`, `Closes #NNN`, `Co-Authored-By:`) and changed paths into one record per commit. | Implemented: `rust/src/history_context/commits.rs` (`import_commits`, `formalize_commit`) records author role, committer date, subject plus body as content, every changed path as `path:` evidence, the `Refs`/`Closes` trailers as `issue:` evidence and the conversation id, and every `Co-Authored-By:` trailer (the seed's `coauthor_trailer` row in `data/seed/history-formalization.lino`, read by `coauthors` in `rust/src/history_context/items.rs`) as `coauthor:<name>` evidence. Pinned by `commit_formalization_extracts_trailers_and_changed_symbols` and `coauthor_trailers_become_evidence` in `rust/tests/unit/issue_1180_history_context.rs`. The seed rows were silently ignored before this change because `HistoryRules::from_seed_text` did not descend under the `history_formalization` root; `rules_seed_rows_override_the_defaults` pins the fix. The importer passes its record format as `--format=` since 46d45c9e1. |
| R1180-2 | For every changed `.rs` path the importer runs `self_ast::ast_census` on the pre- and post-image blobs (`es_meta` for `.js`/`.ts`) and records which top-level items differ, not only which paths changed. | Implemented: `diff_symbols` reads both blobs with `git show` and, besides the census histogram delta, records each named top-level item that was added (+1), removed (-1) or modified (0) as `symbol:<path>#<keyword> <name>` evidence (`diff_named_items` in `rust/src/history_context/items.rs`). The item keywords (`fn struct enum trait ...` for Rust, `function class const ...` for JS/TS), the span keyword `impl` and the modifiers (`pub async export ...`) are seed rows. Pinned by `changed_items_are_recorded_by_name` in `rust/tests/unit/issue_1180_history_context.rs`. The names come from a line-level scan of the seed's keywords, not from the AST: an item opened inside a macro or on an indented line is not named. |
| R1180-3 | An issue/PR importer reuses `github_logs`'s capture and formalizes title, body, labels, state transitions and issue↔PR/commit links. | Implemented 2026-10-07: besides title plus body, labels, the current state and the `Refs`/`Closes`/merge links, `formalize_issue_or_pull` (`rust/src/history_context/github.rs`) now records each body line that opens with the seed's requirement marker and a number as `requirement:R<n> <statement>` evidence (`requirement_statements`, `rust/src/history_context/statements.rs`; a prose reference such as `R1180-3` is not a statement), and the capture's `createdAt`/`closedAt`/`mergedAt` stamps as dated `state:<state>@<timestamp>` transitions in chronological order (`state_transitions`). The states, their timestamp fields, the marker, its leads and the evidence prefixes are the `state_transition`, `state_evidence` and `requirement_statement` rows of `data/seed/history-formalization.lino`; `formal-ai github-logs` now captures `closedAt` (issues) and `closedAt,mergedAt` (pull requests) so the transitions are dated. Pinned by `issue_bodies_formalize_into_requirement_statements_and_dated_transitions` in `rust/tests/unit/issue_1180_history_context.rs` and its JS twin in `rust/tests/web/issue-1180-history-statements-lineage.test.mjs`. Boundary: transitions are those the capture dates (opened, closed, merged); a reopen-then-close cycle shows only the last close, because the capture has no timeline API. |
| R1180-4 | A comments/reviews importer formalizes each comment and review as one record with author, body and timestamp, linked to its parent issue or PR. | Implemented: comment and review batches in `rust/src/history_context/github.rs` become `review` events whose conversation id is `issue-N`/`pr-N` and whose evidence names the parent; covered by `issue_and_pr_import_links_commit_to_source_issue` in `rust/tests/unit/issue_1180_history_context.rs`. |
| R1180-5 | A CI-run importer formalizes each Actions run (`databaseId`, `workflowName`, `conclusion`, `headSha`, `jobs`) into one record per run, carrying the failing step and error text when the run failed. | Implemented: `import_ci_runs` with `failing_step_lines` in `rust/src/history_context/github.rs`, pinned by `ci_run_import_carries_failing_steps` in `rust/tests/unit/issue_1180_history_context.rs`. |
| R1180-6 | Every importer is incremental from a stored cursor, and two back-to-back runs with no new history add zero records. | Implemented: `RepositoryHistoryCursor`, `import_incremental` and the id-deduplicating `write_repository_history` in `rust/src/history_context/cursor.rs`, pinned by `incremental_import_is_idempotent` and `incremental_import_only_advances_past_the_watermark` in `rust/tests/unit/issue_1180_history_context.rs`. |
| R1180-7 | All five record kinds are `MemoryEvent` values with `kind` in `commit / issue / pull_request / review / ci_run`, queryable through the existing memory query language with no schema change. | Implemented: the kind spellings and id prefixes are seed rows in `data/seed/history-formalization.lino`; the lineage `SELECT id FROM memory WHERE kind = 'pull_request' AND evidence LIKE '%issue:1014%'` runs through the unchanged `compile_memory_query`/`execute_memory_query` in `issue_and_pr_import_links_commit_to_source_issue` (`rust/tests/unit/issue_1180_history_context.rs`). |
| R1180-8 | The lineage query for `scripts/check-self-development-release.rs` returns exactly the six commits `git log --follow` lists, each with its issue and pull request. | Implemented with one caveat: `on_this_repo_check_self_development_release_lineage` in `rust/tests/unit/issue_1180_history_context.rs` asserts all six commits (`88d368a5b`, `02f590106`, `96f405e0d`, `aa6a5d085`, `9efeb735c`, `33451d012`), chronological order, and `issue-1014`/`pr:1015` on the introducing commit. The issue and pull request of the five later commits are not asserted, and the test returns early on a shallow clone. |
| R1180-9 | A `formal-ai repository-history import / query` subcommand exposes the importer, following the `cli_github_logs` pattern. | Implemented: `formal-ai repository-history import` and `formal-ai repository-history query <SQL>` (`rust/src/cli_repository_history.rs`, wired in `rust/src/main.rs`) run `import_incremental` and the read-only `query_repository_history` (`rust/src/history_context/query.rs`, ANSI SQL through the unchanged memory query language). The library half is pinned by `the_repository_history_store_answers_a_query` in `rust/tests/unit/issue_1180_history_context.rs`; the argument parsing itself has no test. |
| R1180-10 | `formal-ai chat` answers "why does the self-development status fail?" (and the #1180 probe "what does `evaluate_calculation` do?") from the threshold, the commit range and the rule's source issue. | Partial 2026-10-07: the `repository_lineage` solver route (`handle_repository_lineage` in `rust/src/history_context/lineage.rs`, rank 162 in `data/seed/handler-precedence.lino`, before formalization and search) answers a lineage question about a repository path from that path's `git log --follow` history: the commits oldest first, the issue the introducing commit was made for (its trailer) and the pull request whose merge delivered it, each read through the seed's own trailer and merge patterns; an unrecorded one is said to be unrecorded. It claims only when a seeded `lineage_cue` phrase (en/ru/hi/zh/es, `data/seed/history-formalization.lino`) and a path that exists in the working repository are both present, so a cue word alone never claims (#1175). The prose is the `repository_lineage` records of `data/seed/multilingual-responses-formalization.lino` in five languages. Pinned by `lineage_subjects_need_a_cue_and_a_path`, `lineage_answer_names_the_commits_issue_and_unrecorded_pull_request` and `chat_answers_a_lineage_question_from_this_repositorys_history` (skipped on a shallow clone) in `rust/tests/unit/issue_1180_history_context.rs`; JS twin `js/agentic/crate/history_lineage.mjs`, pinned by `rust/tests/web/issue-1180-history-statements-lineage.test.mjs`. Still open: "why does the self-development status fail?" needs the threshold and commit range explained, not only the lineage, and "what does `evaluate_calculation` do?" needs a definition lookup (the `repository_qa` class); symbol lineage (`git log -S`) is not routed. The browser worker has no repository, so the route is native-only (an `exempt_lane` in the routing-probe budget). |
| R1180-11 | Three-roots parity: the importer is translated to the JS and TS roots. | Partial 2026-10-07: the JS root now carries the pure core (`js/agentic/crate/history_context.mjs`, including the new `stateTransitions` and `requirementStatements`), the github-logs importers (`js/agentic/crate/history_github.mjs`: `classifyLogFile`, `formalizeIssueOrPull`, `formalizeReview`, `importIssuesAndPulls`, `failingStepLines`, `importCiRuns` over `{name, text}` file entries) and the lineage route's claim and answer (`js/agentic/crate/history_lineage.mjs`), pinned by `rust/tests/web/agentic-history-context.test.mjs` and `rust/tests/web/issue-1180-history-statements-lineage.test.mjs`. The TS root exists: `scripts/translate-es.mjs` now renders `js/agentic/**/*.mjs` into `ts/agentic/**/*.mts` and `--check` gates it (`rust/tests/web/translate-es.test.mjs`). Still open: running git and reading/writing the store and cursor files have no JS twin, and the native `formal-ai translate` leg does not render the `.mts` set (only the JavaScript translator does). |
