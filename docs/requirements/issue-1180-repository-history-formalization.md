## Issue #1180 Repository History as Formal Context

Issue [#1180](https://github.com/link-assistant/formal-ai/issues/1180) (E145,
part of the E127 umbrella #1183) asks for the repository's full history —
commits, issues, pull requests, comments, reviews and Actions runs — to be
formalized into records the solver can query, so lineage questions ("which
issue asked for X and which pull request delivered it") have an answer.
R1180-1 through R1180-8 are the issue's own numbered requirements; R1180-9
through R1180-11 are derived from its "What to build", "How to test" and
"Depends on" sections so that nothing the issue asks for goes untracked. The
timeline, root causes and verification live in
`docs/case-studies/issue-1180/`.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1180-1 | A commit importer walks `git log` on the working repository and formalizes each commit's author, committer date, subject, body, trailers (`Refs #NNN`, `Closes #NNN`, `Co-Authored-By:`) and changed paths into one record per commit. | Partial: `rust/src/history_context/commits.rs` (`import_commits`, `formalize_commit`) records author role, committer date, subject plus body as content, every changed path as `path:` evidence, and the `Refs`/`Closes` trailers as `issue:` evidence and the conversation id, pinned by `commit_formalization_extracts_trailers_and_changed_symbols` in `rust/tests/unit/issue_1180_history_context.rs`. `Co-Authored-By:` stays only inside the content text — no trailer rule in `data/seed/history-formalization.lino` turns it into evidence. The importer passes its record format as `--format=` since 46d45c9e1; before that the format string reached `git log` as a revision. |
| R1180-2 | For every changed `.rs` path the importer runs `self_ast::ast_census` on the pre- and post-image blobs (`es_meta` for `.js`/`.ts`) and records which top-level items differ, not only which paths changed. | Partial: `diff_symbols` reads both blobs with `git show` and diffs them, but what it records is the census node-kind histogram delta (`symbol:function_item`) for Rust and a single `token_count` delta from `es_meta::extract` for JS/TS — item kinds, not the names of the functions, structs or impls that changed. Pinned by `commit_formalization_extracts_trailers_and_changed_symbols` in `rust/tests/unit/issue_1180_history_context.rs`. Without the `meta-language` feature the Rust census is compiled out and no symbols are recorded. |
| R1180-3 | An issue/PR importer reuses `github_logs`'s capture and formalizes title, body, labels, state transitions and issue↔PR/commit links. | Partial: `import_issues_and_pulls` (`rust/src/history_context/github.rs`) reads the JSON files `formal-ai github-logs` writes, records title plus body as content, labels as `label:` evidence, the current state as the event intent, and `Refs`/`Closes`/merge links, pinned by `issue_and_pr_import_links_commit_to_source_issue` in `rust/tests/unit/issue_1180_history_context.rs`. Two parts are still missing: the body is stored as text, not formalized into requirement statements, and only the current state is kept, not the sequence of state transitions. |
| R1180-4 | A comments/reviews importer formalizes each comment and review as one record with author, body and timestamp, linked to its parent issue or PR. | Implemented: comment and review batches in `rust/src/history_context/github.rs` become `review` events whose conversation id is `issue-N`/`pr-N` and whose evidence names the parent; covered by `issue_and_pr_import_links_commit_to_source_issue` in `rust/tests/unit/issue_1180_history_context.rs`. |
| R1180-5 | A CI-run importer formalizes each Actions run (`databaseId`, `workflowName`, `conclusion`, `headSha`, `jobs`) into one record per run, carrying the failing step and error text when the run failed. | Implemented: `import_ci_runs` with `failing_step_lines` in `rust/src/history_context/github.rs`, pinned by `ci_run_import_carries_failing_steps` in `rust/tests/unit/issue_1180_history_context.rs`. |
| R1180-6 | Every importer is incremental from a stored cursor, and two back-to-back runs with no new history add zero records. | Implemented: `RepositoryHistoryCursor`, `import_incremental` and the id-deduplicating `write_repository_history` in `rust/src/history_context/cursor.rs`, pinned by `incremental_import_is_idempotent` and `incremental_import_only_advances_past_the_watermark` in `rust/tests/unit/issue_1180_history_context.rs`. |
| R1180-7 | All five record kinds are `MemoryEvent` values with `kind` in `commit / issue / pull_request / review / ci_run`, queryable through the existing memory query language with no schema change. | Implemented: the kind spellings and id prefixes are seed rows in `data/seed/history-formalization.lino`; the lineage `SELECT id FROM memory WHERE kind = 'pull_request' AND evidence LIKE '%issue:1014%'` runs through the unchanged `compile_memory_query`/`execute_memory_query` in `issue_and_pr_import_links_commit_to_source_issue` (`rust/tests/unit/issue_1180_history_context.rs`). |
| R1180-8 | The lineage query for `scripts/check-self-development-release.rs` returns exactly the six commits `git log --follow` lists, each with its issue and pull request. | Implemented with one caveat: `on_this_repo_check_self_development_release_lineage` in `rust/tests/unit/issue_1180_history_context.rs` asserts all six commits (`88d368a5b`, `02f590106`, `96f405e0d`, `aa6a5d085`, `9efeb735c`, `33451d012`), chronological order, and `issue-1014`/`pr:1015` on the introducing commit. The issue and pull request of the five later commits are not asserted, and the test returns early on a shallow clone. |
| R1180-9 | A `formal-ai repository-history import / query` subcommand exposes the importer, following the `cli_github_logs` pattern. | Pending: no CLI module or subcommand exists; the importer is reachable only as the library module `formal_ai::history_context`. |
| R1180-10 | `formal-ai chat` answers "why does the self-development status fail?" (and the #1180 probe "what does `evaluate_calculation` do?") from the threshold, the commit range and the rule's source issue. | Pending: no solver handler reads the repository-history store; the `repository_qa` row of `docs/llm-task-parity.md` still records the 0.347.0 self-description answer. |
| R1180-11 | Three-roots parity: the importer is translated to the JS and TS roots. | Pending: there is no JS or TS twin of `history_context`; only the seed is mirrored (`rust/embedded/data/seed/history-formalization.lino`). |
