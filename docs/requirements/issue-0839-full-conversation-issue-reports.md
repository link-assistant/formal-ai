## Issue #839 Full-Conversation Issue Reports

Issue [#839](https://github.com/link-assistant/formal-ai/issues/839) reports
that an agentic `report issue` filed nothing a maintainer could act on: issue
[#838](https://github.com/link-assistant/formal-ai/issues/838) carried 271 KB of
base64 HTTP proxy traffic instead of the conversation, named a session no
harness had ever heard of, was cut mid-record by `tail -c 12000`, attached a
gist literally named `formal-ai-report.XXXXXX.lino`, and reported success
throughout. The requirements below make the agentic report the same document
the web reporter has always produced, and make every way of failing loud.

| ID | Requirement | Status |
| --- | --- | --- |
| R494 | A report must export the caller's real harness session, not a value derived from the conversation's text. | The HTTP server records `x-formal-ai-dialog-id` per request (`src/dialog_log.rs`), `report_issue.rs::dialog_id` reads it, and falls back to `--session latest` — which `formal-ai context session` resolves from the live harness — rather than to a hash. Covered by `conversations_sharing_a_first_message_do_not_collide`, `the_session_subcommand_resolves_the_session_this_shell_is_inside`, and `two_conversations_sharing_a_first_message_file_different_contexts`. |
| R495 | A named `--source` that cannot be exported must fail loudly instead of degrading to a different capture. | `src/cli_context.rs` errors on an unexportable named source and on an export with no `message` records; the generated script runs under `set -eu`, so nothing reaches `gh`. Covered by `harness_source_fails_loudly_instead_of_returning_the_server_log`, `an_empty_export_fails_instead_of_reporting_success`, and `an_unexportable_session_fails_before_gh_is_reached`. |
| R496 | The server must record a conversation, distinct from the HTTP proxy trace, so `--source server` and `--source both` mean something. | `src/dialog_conversation.rs` writes one conversation record per exchange alongside the proxy frames; `both` merges the harness and server records into one document. Covered by `server_export_carries_conversation_turns_not_only_proxy_frames` and `both_merges_harness_and_server_records_into_one_document`. |
| R497 | One shared builder must produce the identical report document for web, CLI, desktop, Telegram, and VS Code. | `src/issue_report.rs` owns the six sections and the title; `src/web/app/issue-report.js` mirrors it for the wasm worker, which cannot link the Rust core, and `src/web/app/main.jsx` only gathers facts and labels. `tests/integration/issue_839_report_parity.rs` renders the same fixture through both and fails on drift. |
| R498 | The title must quote what the conversation was about: drop the report request itself, quote `` `first` + `last` `` when two subjects fit, otherwise the first alone on a word boundary, and never the bare default while a user turn exists. | `issue_title` in `src/issue_report.rs`; covered by `two_subjects_are_titled_first_plus_last`, `a_single_subject_is_quoted_on_its_own`, `an_oversize_subject_is_truncated_on_a_word_boundary`, `an_answered_report_request_can_still_be_a_subject`, and `the_default_title_is_never_used_when_a_user_turn_exists`. |
| R499 | Truncation must never cut inside a Links Notation record; oversize context attaches in full with an explicit `omitted N` marker. | `truncate_records` in `src/issue_report.rs` keeps whole records from both ends and names the count it dropped; `--oversize gist` uploads the complete context, `--gist-visibility` is an explicit documented choice (`docs/report-issue.md`). Covered by `truncation_never_splits_a_links_notation_record` and `a_byte_slice_of_the_same_export_loses_the_record_boundaries`. |
| R500 | The generated script must be a real, testable program: every command verified with `command -v`, every scratch path a real filename. | `src/agentic_coding/report_script.rs` renders `set -eu`, a `command -v` preflight per program, and a `mktemp -d` scratch directory removed on exit. Covered by `a_missing_command_fails_loudly_and_files_nothing`, `the_scratch_template_is_expanded_before_anything_is_written`, and the end-to-end `the_generated_script_files_the_full_conversation_in_all_six_sections`, which executes the script against a stubbed `gh` and asserts on the file `gh issue create` actually received. |
