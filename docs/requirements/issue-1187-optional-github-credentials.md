## Issue #1187 Optional GitHub Credentials in Every Workflow

Issue [#1187](https://github.com/link-assistant/formal-ai/issues/1187) (E151,
part of the E127 umbrella #1183): tokens are "not mandatory, but optional in
all cases". One resolver chooses a GitHub App, then one `AUTOMATION_TOKEN`
secret, then `github.token`; bot pull requests get their checks by dispatch
instead of waiting for approval; isolated tests use orphan branches in this
repository; cross-repository work degrades to a report. R1187-1 through
R1187-6 are the issue's R1–R6; R1187-7 and R1187-8 are its automated and
manual tests. Existing-file migrations are deferred edits recorded in
`docs/integration-manifest.md`; the history and the #1124 check evidence
live in `docs/case-studies/issue-1187/`.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1187-1 | Every workflow that writes to GitHub takes its token from one resolver — GitHub App (`AUTOMATION_APP_ID` + `AUTOMATION_APP_PRIVATE_KEY`) → `AUTOMATION_TOKEN` → `github.token`; `FORMAL_AI_BOT_TOKEN` is replaced; nothing skips or fails on a missing token; the layer is printed to the log and the job summary. | Partial: `.github/actions/automation-token/action.yml` resolves the three layers, writes the layer to the log and `GITHUB_STEP_SUMMARY`, and exposes `can-create-repositories` (true only at the App layer); `cross-org-duplication.yml`, `dependencies-latest.yml` and `e2e-isolation.yml` use it. Pinned by `the_resolver_action_implements_the_three_layers` and `no_workflow_reads_a_foreign_token_secret` in `rust/tests/unit/issue_1187_credentials.rs`. `self-authored-pull-request.yml` still reads `secrets.FORMAL_AI_BOT_TOKEN` (with a `github.token` fallback); its migration is a deferred edit row in `docs/integration-manifest.md`. The action is a local mirror of link-foundation/.github `resolve-github-token` (link-foundation/.github#1), not a call to it. |
| R1187-2 | At layer `default`, the workflow that opened or pushed the pull request dispatches every `pull_request` workflow on the head commit; `layered-ci.yml`, `evidence-check.yml` and `workflows.yml` gain `workflow_dispatch` with `mode: checks`. | Partial: `.github/actions/dispatch-checks/action.yml` runs `gh workflow run` for each `pull_request` workflow on the head sha and warns on any that lacks the trigger, pinned by `the_dispatcher_dispatches_pull_request_workflows` in `rust/tests/unit/issue_1187_credentials.rs`. No workflow calls it yet, and the three workflows still have no `workflow_dispatch` trigger — both are deferred edit rows in `docs/integration-manifest.md`. |
| R1187-3 | `release.yml` gets a checks-only dispatch mode that is the default, and every release, publish and tag job requires an explicit release mode and `github.ref == 'refs/heads/main'`. | Pending: `release_mode` still defaults to `instant` and the `workflow_dispatch` branches near lines 193, 263, 295, 393 and 590 still run on any ref; the exact edit is recorded in `docs/integration-manifest.md`. No test checks it. |
