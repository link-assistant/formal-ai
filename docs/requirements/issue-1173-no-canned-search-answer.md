## Issue #1173 No Canned Search Answer in the Unknown-Reasoning Fallback

Issue [#1173](https://github.com/link-assistant/formal-ai/issues/1173) (E138)
deletes the descriptive "Web search requested for `…`" paragraph as an answer
surface and makes the unknown-reasoning fallback execute its web search. The
source analysis, the deleted answer arms, and the evidence live in
`docs/case-studies/issue-1173/`.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1173-1 | The unknown-reasoning fallback runs the executed search for its focus and answers from the captured statements with citations; offline it answers with the existing `web_search_unavailable` response plus what the offline cache holds. | Implemented: the fallback arm in `rust/src/solver_unknown_reasoning.rs` hands its focus to `answer_web_search_query`, which now executes through `execute_web_search_answer` (`rust/src/solver_handlers/web_requests/live_search.rs`) against the process source cache. Captured sources answer via issue #709 statement fusion with per-statement citations; an offline or cache-miss run still reads the cache and then degrades to the localized `web_search_unavailable` response naming the focus. Pinned by `rust/tests/unit/issue_1173_fallback_executes_search.rs`. |
| R1173-2 | `answer_web_search_query`'s descriptive text is no longer an answer anywhere; it survives only as narration of the planned search (or is deleted). | Implemented by deletion: every `format!` arm of the old paragraph (default, latest-news, open-research; en and ru) is removed from `rust/src/solver_handlers/web_requests.rs`, and `try_web_search` delegates to the executed path. The provider list and fusion formula survive only as log events (`web_search:provider_planned`, `web_search:fusion_planned`) on the unavailable path — narration in the reasoning trace, never the answer.
