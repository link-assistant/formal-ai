## Issue #1161 Client Registry Names the Agent Config Env

Issue [#1161](https://github.com/link-assistant/formal-ai/issues/1161) (E126)
makes the client registry declare *how* a client is pointed at its config —
the env var that relocates it — instead of implying an `XDG_CONFIG_HOME`
relocation that also moves `gh`'s and git's config and breaks GitHub
authentication inside the session. The incident analysis, the per-client
evidence, and the fix live in `docs/case-studies/issue-1161/`.

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1161-1 | Every `global_configs` entry in `data/seed/client-integrations.lino` can declare the environment variables that relocate its own config file (`config_env "VAR"` children), parsed into a new `ClientIntegrationGlobalConfig::config_env: Vec<String>`; entries whose file has no relocation variable declare an empty list. | Implemented: the `config_env` field and parser arm in `rust/src/seed/client_integrations.rs`, filled in `data/seed/client-integrations.lino` (and its committed `rust/embedded/` mirror) only where in-repo evidence exists. Pinned by `rust/tests/unit/issue_1161_client_registry_env.rs`. |
| R1161-2 | `agent` names `LINK_ASSISTANT_AGENT_CONFIG` (config file) and `LINK_ASSISTANT_AGENT_CONFIG_DIR` (directory); `codex` and the `t3code` OpenAI-protocol entry name `CODEX_HOME`; `opencode`, `opencode-vscode` and `opencode-desktop` name `OPENCODE_CONFIG` and `OPENCODE_CONFIG_DIR`. | Implemented in the same seed file. Evidence per client: agent — the issue itself and the wrapper's own `LINK_ASSISTANT_AGENT_CONFIG_CONTENT` one-shot mechanism; codex — `docs/configuration/output-sessions.md` (`$CODEX_HOME/sessions/…`), `experiments/agentic_cli_matrix/README.md` (`CODEX_HOME` → a directory holding `config.toml`) and `rust/tests/issue_760.rs`; t3code — its own ephemeral block relocates the same `config.toml` via `CODEX_HOME` (`docs/configuration/t3-code.md`); opencode family — each block's own ephemeral `config_env "OPENCODE_CONFIG"` / `config_dir_env "OPENCODE_CONFIG_DIR"`. Pinned by the per-client assertions in the same test file. |
| R1161-3 | The declaration is a registry surface: `formal-ai clients --format json` carries it additively as `global_configs[].config_env` (plus the one-shot `config_env`/`config_dir_env`/`config_content_env`/`temp_home_env` top-level fields), and `formal-ai clients` prints it on each `global[...]` line. | Implemented in `rust/src/cli_clients.rs`. Additive only — the matrix (`experiments/agentic_cli_matrix/run_leg.sh`) still reads exactly the `verification.*` fields it read before. The projection is a bin module and is reviewed, not unit-tested; the underlying parsed data is what the test pins. |
| R1161-4 | A host integration contract is documented: a host that needs a task-local client config sets the declared variable and must not relocate `XDG_CONFIG_HOME` or `HOME` (the 2026-09-27 `gh`-auth incident, link-assistant/hive-mind#2314). | Implemented: the "Host integration contract" section and the *Relocate via* column in `docs/configuration/agentic-clis.md`, the registry-surface note in `docs/testing/agentic-cli-tools.md`. |
| R1161-5 | Clients whose global entry is a shell profile (`gemini`, `claude`, `qwen`, `aider`) or a fixed path with no evidenced variable (`cursor`, `grok`) declare none; no variable is fabricated. | Implemented and pinned by `entries_without_a_relocation_variable_declare_none` in the same test file. |
| R1161-6 | Hive Mind switches its Formal AI agent launcher from the `XDG_CONFIG_HOME` relocation to `LINK_ASSISTANT_AGENT_CONFIG_DIR`/`LINK_ASSISTANT_AGENT_CONFIG`. | Cross-repo (link-assistant/hive-mind#2314): this repository's part — naming the variables as registry data and documenting the contract — is delivered here; the launcher change itself is tracked in the Hive Mind repository and is not confirmed from this repo. |
| R1161-7 | The declared relocation actually works end to end: the agent CLI is started with `LINK_ASSISTANT_AGENT_CONFIG(_DIR)` pointing at a temporary config directory and serves the session from it (pull-request follow-up row: the smoke test half of the registry surface). | Open follow-up, cross-repo: the end-to-end smoke test needs the agent CLI's own repository to drive the launch; this repo pins the parsed declaration (`issue_1161_client_registry_env.rs`, including the embedded-mirror sync) and documents the contract (`docs/configuration/agentic-clis.md`), but no test here launches a client against a relocated config. |
