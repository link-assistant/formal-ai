## Issue #918 Minimal-Core Boundary And Seed-Metadata Audit

Issue [#918](https://github.com/link-assistant/formal-ai/issues/918) turns E71's
architectural goal into audited data and shrink-only gates. See PR #986 and
`docs/case-studies/issue-918/`.

| ID | Requirement | Status |
| --- | --- | --- |
| R918-1 | Define the smallest acceptable compiled core and classify everything else as data or migration debt. | Implemented in `docs/design/minimal-core-boundary.md`: meta algorithm, link store, generic interpreters, and host surfaces are the only four core categories. Pinned by `rust/tests/unit/issue_918.rs`::`boundary_document_names_the_only_four_compiled_core_categories`. |
| R918-2 | Inventory every handler source recursively and record migrate, promote, or delete with a reason. | `data/meta/core-boundary-ledger.lino` covers all 88 recursively counted handler sources: 37 are promoted generic interpreters that read their vocabulary from seed data and 51 remain migration debt (`disposition migrate`, each with its data target and reason). `scripts/check-minimal-core-boundary.rs` ratchets the 19,494 outside-core lines two ways (growth needs a recorded note; shrinkage lowers the baseline). Per-handler progress lives in `data/meta/handler-migration-ledger.lino` (46 migrated, 25 pending, 26 justified-native of 97 as of the 2026-10-08 R914-6 algorithm and document batches, which took `try_algorithm` out of Rust and `document_request.rs` from 654 to 357 lines, pinned by `rust/tests/unit/issue_918_handler_rules_batch.rs` and `rust/tests/unit/issue_699_handler_migration.rs`), so the row is partial until the 25 pending rows reach zero. |
