| R67 | Search external sources when local links are insufficient and cache accesses with provenance and refresh policy. | **Implemented (issue #1138 B1).** When local links are insufficient — the normalized prompt carries surfaces no seeded meaning accounts for — the universal loop's external search (`record_external_search` in `rust/src/solver_search.rs`, called from `UniversalSolver` in `rust/src/solver.rs`) asks the trusted sources what those surfaces mean: `concept_lookup::unknown_surfaces` derives them and `concept_lookup::lookup_surface` consults the registered sources through `CachedSourceClient` (live fetch only when the runtime opted in; offline runs record `search:external skipped:offline` instead). Fetches go through the same source cache that carries `source:http`, `fetched_at=`, and `sha256=` provenance (R79), misses log `concept_lookup:miss` with the consulted sources beside them, and opted-out sources log `concept_lookup:disabled`, so an answer that used a source stays attributable to it. The explicit HTTP-request path (`try_http_fetch_with_offline` in `rust/src/solver_handlers/web_requests.rs`) tries the curated registry first, then performs a real cached fetch and returns up to 8,000 bytes of the body, recording `policy:offline` instead when offline. The earlier fabricated provenance (an `example.org` URL digested from the prompt rather than from retrieved content) was removed by #843 (PR #853, 2026-07-29); `rust/tests/unit/specification/source_cache.rs` pins that local prompts never leak fake source links and that external lookups record their source URL. |
