## Issue #1188 Compact Inputs and Useful Coding Work

The owner added this requirement on 2026-10-09 while continuing
[PR #1188](https://github.com/link-assistant/formal-ai/pull/1188):
"we should strive for Formal AI to provide high quality result with small
input usually smaller than useful output (net code changes)."

| ID | Requirement | Status / Evidence |
| --- | --- | --- |
| R1188-U31 | For expansion-suitable coding and self-coding, Formal AI should usually turn a concise statement of the desired behavior into a larger useful, validated net code change by discovering and reusing repository knowledge. Keep correct deletion, refactoring and small repairs useful even when output is smaller; no mandatory growth for mathematics or other tasks. | Partial: the goal and measurement contract are recorded in [coding-amplification.md](../case-studies/pull-request-1188/coding-amplification.md). The self-coding suite has three passing fixture controls and zero of seven requested feature-composition checks; concise autonomous feature delivery is not established. |
| R1188-U32 | Record original task bytes, all retry instructions, reviewed patches, observed repository context, tool receipts, exact changed-source identities, acceptance checks and authorship separately. Compare task-only and complete observed-input ratios; record actual model usage and prices before claiming token or monetary savings. | Partial: `experiments/formal_ai_subagent/coding-amplification.mjs` measures these byte categories and source-bound checks; `rust/tests/web/coding-amplification.test.mjs` rejects omitted first attempts, source drift and false patch attribution. Byte proxies are not token counts. Complete coordinating-model usage and monetary savings remain unmeasured. |
| R1188-U33 | Correctness, scope, maintainability, security and independent acceptance take priority over amplification. Never add redundant code, oversized literals, repeated wrappers, comments, generated mirrors or evidence just to improve the ratio. A supplied executable patch is applied work, not autonomous synthesis. | Partial: `rust/tests/web/coding-amplification.test.mjs` excludes comments, formatting, literal payload length, unchanged files, generated mirrors, documentation and evidence from the code proxy; reviewed patches cannot enter the autonomous numerator. Semantic usefulness, unused-code padding and independent test quality still require review. |
| R1188-U34 | CI should preserve and report a fixed representative cohort of coding and self-coding attempts, including failures, acceptance rate, useful changes and compact-input amplification. Establish an observed baseline before enforcing a cohort ratchet; do not replace correctness with a universal per-task output-size floor. | Partial: the existing JavaScript CI shards discover `rust/tests/web/coding-amplification.test.mjs` automatically and enforce accounting, quality binding and negative controls. Representative end-to-end task cohorts, separate self-coding baselines, usage integration and a reviewed improvement ratchet remain open. |
| R1188-U35 | Declare each task category and expected input/output size relation before execution. Aim for almost-always expansion for feature/test construction and detailed explanations/proofs; track compression for decisions, numeric calculations, extraction and summaries, and unrestricted repair/refactoring/deletion/translation. Validate usefulness independently, retain failed attempts and exceptions, and never pad outputs or reclassify the cohort after observing outcomes. | Partial: `experiments/formal_ai_subagent/task-relations.mjs` binds original tasks and saved category declarations to exact source/response acceptance and complete cohorts; `rust/tests/web/task-relations.test.mjs` checks real calculation/decision outputs, useful deletion, expansion, source drift, reclassification and failures. The recorded objective is at least95% accepted matching tasks over at least20 declared tasks per category. These are instrumentation fixtures, not a representative Formal AI performance baseline. |
