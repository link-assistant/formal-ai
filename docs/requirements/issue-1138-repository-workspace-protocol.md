## Issue #1138 Repository Workspace Protocol

Repository authoring uses one default-deny protocol, covered by
`rust/tests/unit/repository-workspace/issue_1138_repository_workspace.rs` and
`rust/tests/unit/repository-workspace/issue_1138_locate_targets.rs`.

| ID | Requirement | Status / evidence |
| --- | --- | --- |
| R1138-3-1 | A repository task carries an origin and an exact base commit; a branch name is refused as a base. | Implemented by the repository-workspace request parser; covered by `rust/tests/unit/repository-workspace/issue_1138_repository_workspace.rs`. |
| R1138-3-2 | Named targets are located by repository census or literal/path occurrence; ambiguity resolves to no target. | Implemented by `rust/src/repository_workspace/locate.rs`; covered by `rust/tests/unit/repository-workspace/issue_1138_locate_targets.rs`. |
| R1138-3-3 | Named tests run and record command, exit code, and output before an obligation can be satisfied. | Implemented by the verification stage; covered by `rust/tests/unit/repository-workspace/issue_1138_named_tests.rs` and `rust/tests/unit/repository-workspace/issue_1138_repository_workspace.rs`. |
| R1138-3-4 | The offered patch is a unified diff computed from the tree and verified against the exact base. | Implemented by the workspace outcome; covered by `rust/tests/unit/repository-workspace/issue_1138_repository_workspace.rs`. |
| R1138-3-5 | SWE-bench, the coding ladder, and self-authoring consume the same protocol document. | Partial (JS-first parity): Rust delivers the live callers. JavaScript now also executes the structural clone, locate, read, edit, verify and diff stages through an injected file/process port (js/agentic/crate/repository_workspace_runner.mjs and repository_workspace_stages.mjs), and runAuthoringWith in repository_workspace_authoring.mjs iterates the same document through caller-owned stage ports. rust/tests/web/repository-workspace-runners.test.mjs pins identical trace stage names for the three caller labels, removing serve from the document, recording the opened authoring commit gate before its callback, base mismatch stops, ambiguity, default-deny command shapes and honest verification failures. `data/meta/repository-workspace-protocol.lino` is the one stage list of all three callers. It declares nine stages (clone, locate, read, serve, edit, session, verify, diff, commit), each with an `editor`: `any`, or `agent_session` for spawning `formal-ai serve` and harvesting the Agent CLI session id, which are data rather than a branch in code. SWE-bench (`external_benchmarks::solve_repository_case`) and the coding ladder (`formal-ai solve --task`) run it through `WorkspaceProtocol::execute`; self-authoring (`formal-ai solve --produces`, behind `scripts/author-change-with-formal-ai.sh`) runs it through `authoring_loop::run_authoring_with`, which iterates the stages of the document instead of a separate loop. All three write the same `repository-protocol.lino` (`repository_workspace::trace::ProtocolTrace`), one stage line per declared stage with its status. Covered by `rust/tests/unit/ci-cd/protocol_callers.rs` (the three callers, run against one local repository with fake serve and Agent CLI executables, record identical stage names; a document without the serve stage spawns no server; the committed trace records the opened commit gate), `rust/tests/unit/specification/repository_workspace_protocol.rs`, `rust/tests/unit/repository-workspace/issue_1138_repository_workspace.rs`, `rust/tests/unit/agentic-coding/issue_848_coding_ladder.rs` and `rust/tests/web/issue-1138-protocol-trace.test.mjs`; the Rust tests are new in round 14 and run first in CI. Remaining parity gap: JavaScript live SWE-bench and solve callers have not yet adopted the injected runner; authoring stage side effects (isolated workspace, server readiness, Agent CLI session and artifact/trailer contract) remain caller-owned ports with no complete Node adapter. The JavaScript location stage supports injected census resolution and exact semantic literal declarations, but lacks the native partial-census ranking fallback. The structural runner refuses commit; the authoring loop opens its commit port only by explicit request and observed earlier stages. |
| R1138-3-6 | Commands are default-deny and allowed by program, subcommand, and argument shape from seed data. | Implemented by the repository command allowlist; covered by `rust/tests/unit/repository-workspace/issue_1138_command_allowlist.rs`. |
| R1138-3-7 | Authoring refuses commits by default; an allowed commit carries all self-hosting trailers and exact model evidence. | Implemented by `run_solve`, which is default-deny, and the authoring wrapper `scripts/author-change-with-formal-ai.sh`, reduced to that entry point, which passes `--commit` only when its caller asks (the self-authoring action does); the produced commit payload passes the canonical attribution parser. Covered by `rust/tests/unit/ci-cd/docker_resource_hygiene.rs` (`the_authoring_wrapper_commits_only_when_asked`), `rust/tests/unit/issue_1138_solve_cli.rs` and `rust/tests/unit/specification/self_hosting_metric/solve_attribution.rs`. |
| R1138-3-8 | A missing prerequisite remains an evidenced unsatisfied need, never a pass or skip. | Implemented by the protocol outcome ledger; covered by `rust/tests/unit/repository-workspace/issue_1138_repository_workspace.rs`. |
| R1138-3-9 | The protocol document is forgettable and regenerates to the same content id. | Covered by `rust/tests/unit/specification/repository_workspace_protocol.rs`. |
