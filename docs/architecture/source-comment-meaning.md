# Source comment meanings

Comments keep their exact UTF-8 text, delimiters and layout in the concrete source model. The comment-meaning API adds structural source/owner/role links and separate documentary propositions. Those propositions confer no execution authority and citations remain unverified references.

The adapter reuses the actual seeded lexicon, relation cues, type constructors and naturalizer. Its finite compositional grammar represents ordered universal/existential bindings, modal obligations/permissions, negation, typed relations and filesystem/exception effects. Definition references are expanded with actual source owners, cycle references and an explicit 64-concept closure limit. Unknown concepts and unsupported clauses remain named needs.

Naturalization reads the same graph and independently re-formalizes the whole wording and every part. It never copies an unknown source sentence as a successful English rendering. The language parameter is open; each actual language result must establish its own round trip. Four-language project documentation translation, general deep formalization, inferred comment/code consistency, fact checking and native production integration remain separate unfulfilled capabilities, recorded in comment-semantic-needs.lino.

The exported API is formalizeComment(input, options), naturalizeComment(model, options), commentMeaningLinks(model), and validateCommentMeaning(model). Attachment identity uses readable source path, source language, owner kind/name and comment role. Numeric positions are not primary identities.
