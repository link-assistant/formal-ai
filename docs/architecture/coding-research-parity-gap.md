# Coding research: bounded parity gap and shared-hook plan

This audit describes the source identified by the accompanying [evidence ledger](../../data/meta/coding-research-parity-gap.lino). It does not certify full discovery, behavior parity, native delivery, or a release. All R1183-G1 through R1183-G5 requirements remain Pending. The ledger records a dated source snapshot: later source changes require a new probe before reusing its conclusions.

## Actual production boundaries

JavaScript reaches `planCodingResearchStep` through `planModuleFunctionResearchStep` and `missingSemanticImplementation` in `js/agentic/planner.mjs`. The route reads the destination and independent test, derives a bounded search query, fetches at most three HTTPS pages of at most 131072 bytes each, validates one pure declaration, rebinds identifier spans, and proposes a typed execution recipe. Only observed client execution and strict nonempty TAP receipts permit verified status.

The corresponding native planner still calls `module_function::plan_module_function_step` directly. Native `module_function/discovery.rs::plan_observed_callable_outcome` reads operands and returns a named missing-contract outcome. It has no equivalent request-local research route. `coding_research_learning.rs::research_coding_skill_gap` is a different interface: the caller supplies source, expected output and reviewer approval; it discovers a rewrite procedure and verifies that supplied input. `discovery_production.rs::cached_or_research` calls that interface. These existing native paths do not establish parity with the new JavaScript code-block and independent-test route.

Both runtimes already have the real `ExecutionRecipe -> command_reroute` hook: `planSymbolicCommandReroute` and `plan_symbolic_command_reroute`. It owns advertised tools, source writes, command observations and the existing three-rung repair budget. Reuse this effect boundary; do not create a second research-specific executor or grant verification authority to discovery prose.

## Existing meta interpreters are narrower

`recipe_interpreter.rs::RecipeProgram::execute` executes trace recorder bindings. Unbound formalize, resolve and answer steps are skipped. `data/meta/coding-discovery-recipe.lino` describes discover/compose/verify stages, but does not turn this recorder interpreter into a search or coding executor.

`skill_procedure.rs::ProcedureHost::perform` and `CompiledProcedure::execute` provide a linear native host walk. The JavaScript twin currently compiles procedures and renders a conformance walk whose output is `kind(input)`. That rendering is not observed search, source derivation, execution or verification. Neither existing surface supplies guarded request-local research continuation on both runtimes.

## Smallest supported canonical selector

The existing `portable-string-v1` profile already accepts explicitly typed string parameters, string equality and nested conditional returns, serializes them through the shared Links IR, and renders production Rust. A finite selector over named string states needs **no language-profile extension**. It can be generated with the existing `stringProgramToMeta`, `assertCompleteStringIR` and `renderStringRust` pipeline, with TypeScript projected by the existing ES translator.

Generating an unused selector would not remove duplicated production behavior: the new native research route and its fact producer do not exist. Wiring native callbacks that merely assert missing derivation or acceptance results would invent the very parity being measured. This packet therefore records the gap instead of adding a disconnected interpreter or a hand-maintained Rust research copy.

The first useful implementation must define one bounded tagged fact snapshot and canonical transition selector, then actually consume it from both planners. Its facts must distinguish unsupported grammar/bindings, complete source/test reads, independent acceptance, query-bound successful search, eligible captured pages, zero/one/multiple proposals, exact existing-source match, write/run observations and reported verification outcome. Unknown or unreported facts must yield a named Gap. Raw source text, task names and complete task answers must not become selector lookup keys.

The existing string profile can express the transition decisions once those facts are observed. It cannot by itself parse tool histories, formalize code captures, validate effects, rebind byte spans, prove independent assertions, or interpret TAP counts. Those semantic primitives must also have shared canonical definitions with generated production consumers, or remain explicitly unsupported. A thin adapter may bind real host observations; it must not conceal a second implementation of those algorithms.

## Reproducible upstream blockers

The authenticated probe uses meta-language commit `eb0574d5528babd3b4aadece81590d8e2230b99b`; all 234 staged source module hashes were rechecked against the previously authenticated exact-pin source manifest. The ledger binds the source graph manifest, the actual Formal AI probe receipt and the current source hashes. The probe called the real upstream `selfTranslate` and `translateProgram` APIs without typed import signatures or repository lowering. It is a raw capability diagnosis, not a committed production projection or native compile result.

At this snapshot the production translation driver scopes `js/agentic/crate` and meta worker modules; `js/agentic/coding_research.mjs` is outside that census. Its imports and budget constants emit, while all nine behavioral helpers are carried. The ledger retains each exact first diagnostic and the separate approximate static blocker set. Notable blockers include untagged objects, collection operations and typed-array construction, regex, exceptions, JSON standard-library calls, optional chaining and imported namespace values. Raising a translated-symbol count or adding an allowlist would not resolve these semantics.

## Required acceptance before parity claims

Use one shared declarative corpus to drive both actual planner routes: original and held-out tasks; complete and failed reads; foreign-query search receipts; HTTP and page-size limits; ambiguous procedures; identifier text inside literals; independent assertion rejection; retries; missing, malformed, empty, skipped and failed TAP; and no-op reuse of already matching verified source. Preserve exact tool arguments, source/hash provenance, effects, terminal disposition and budget boundaries.

JavaScript controls can qualify their actual route locally. Native compilation and real native/client execution remain hosted-only and Pending. A generated selector alone is finite source progress; it cannot close general discovery, cold/warm cache, cross-client delivery, or full JavaScript/TypeScript/Rust parity requirements.
