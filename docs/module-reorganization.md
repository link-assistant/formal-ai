# Module reorganization manifest (issue #954, E102 — architecture review 5.1 + 5.4)

The exact file→destination plan for grouping the solver, world-model,
dreaming and translation families into directory modules with `mod.rs`
re-exports, so file boundaries follow responsibility instead of the
1000-line cap. The map itself already landed in `ARCHITECTURE.md §18`, now
[`docs/architecture/module-map.md`](architecture/module-map.md) (generated by `scripts/generate-module-map.rs`, pinned by
`rust/tests/unit/issue_954_module_map.rs`); this document is the moving
plan the physical `git mv`s follow, one family per pull request.

`solver_handler_how.rs`, `solver_helpers/code.rs`, `solver_helpers/mod.rs`
and the `solver.rs:190` doc line (the parsing body moves home to
`solver/config.rs`, which is its responsibility, not its overflow).

## Public-API rule

Every `mod.rs` re-exports the moved names so `cargo public-api` diffs
empty against the pre-move surface; a deliberate API change is its own
pull request, reviewed on its own diff, never a side effect of a move.
The `git mv`s are pure renames (`git log --follow` keeps blame).

## Landing order and the CI leg

1. `solver/` (largest, dissolves 5 of 6 cap headers)
2. `world_model/` (the 1000-line proof case)
3. `dreaming/` and `translate/` (small, independent)
4. Rewrite the remaining cap-admitting header
   (`calculation_word_problem.rs`) to state the real responsibility — or
   fold the file into `solver/handlers/calculation_word_problem.rs`,
   where the word-problem normalization belongs.

After step 3 the top-level entry count drops by ~30; the issue's
"top-level `src/` entry count < 60" CI leg arms only when the count is
actually below 60 — the same arm-when-true shape as the #1088 evidence
gates, recorded here so nobody has to re-derive the starting number
(273 entries, 227 `.rs`).
