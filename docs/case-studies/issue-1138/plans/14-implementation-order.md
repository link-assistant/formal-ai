# Plan 14 — Implementation order: every leaf of plans 01–13, in one order

Status: generated by the reconciliation leaf of
[`00-root-causes-and-integration.md`](00-root-causes-and-integration.md) §8 on
2026-09-16, after plans 01–13 were reconciled against §4's contracts and against
each other. Nothing here is a new decision: every leaf is a leaf some plan
already owns, and every ordering constraint is either plan 00 §5's dependency
graph or a row of plan 00 §9's reconciliation log.

A leaf is committed alone. The commit message names the plan and the leaf. The
plan's box is ticked in the same commit (plan 00 §7).

## Why this document has no options and no decision

Plans 01-12 each carry root causes, at least three options, a decision with its
rejections, an exact architecture, tests first, leaves and docs, because each
answers a bottleneck. This document answers none: it is **derived**, by plan 00
§8's fourth box, from leaves those plans already own and from orderings plan 00
§5 and §9 already fixed. Adding an options section here would invent a decision
no plan made, which is exactly what plan 00 §6.4 and plan 13's risk 1 forbid.

Where an ordering genuinely was not decided by any plan, it is named in the final
section rather than resolved silently.

## What this document is for

Twelve plans, authored in parallel, own **340 leaves** between them. Read plan by
plan they do not compose: plan 03 stops honestly at `kotlinc: command not found`
unless plan 06 landed first; plan 02 composes nothing new unless plan 01 landed
first; plan 08 cannot add a handler at all unless plan 09 made the ratchet strict
first. This document is the single order in which they do compose, and the wave
grouping is the shape that suits bulk work: write every test, then implement in
dependency stages, then use the result on itself, then make the documents true.

## The order, and why it is this order

Plan 00 §5 fixes the spine:

```
01 lookup ──► 04 formalization ──► 02 composition ──► 05 evidence ──► 06 prerequisites ──► 03 workspace
                                                        │                                     │
                                                        └──► 08 verifiable routing ◄──────────┘
                                                        └──► 07 learning loops
09 ratchet, 10 routing, 12 heuristics: alongside, each leaf consuming 01/04 where it needs meaning
11 docs, 13 carry-over: inputs first (scope), outputs last (numbers)
```

Four constraints the reconciliation added to that spine, each with its plan 00 §9
row:

1. **Contracts before consumers** (plan 00 §7). `src/needs.rs` (leaf C1) and
   `src/execution_evidence.rs` (plan 05's first three leaves) land before
   anything that names `Need` or `Evidence` — which is nine of the twelve plans.
2. **The ratchet is repaired before it is used** (§9 X6). Plan 09 leaves 1–8 make
   `check-debt-ratchet.rs` strict two-sided and unify the three incompatible
   handler-file counts, because plans 03, 06, 08, 10, 11 and 12 all add measures
   to it and an at-or-below checker records an improvement it never enforces.
3. **Plan 06 before plan 03** (plan 00 §5, restated in both plans' headers).
   Recovery exists by the time `Workspace::run` calls it, and plan 06 owns the
   `ExecutionBackend` enum plan 03 consumes (§9 R7).
4. **Plan 05 before plans 07 and 12** (§9 R2, X11, X14). `Evidence` is what a
   `BehaviorDelta`'s two sides are, what an eliminated hypothesis is eliminated
   by, and what `ActionCost::resource_units` is read from.

## Local resource rules

These are rules about the *developer's* machine, not about the system's
behaviour. They exist because this plan set is large enough that running the full
matrix locally on every leaf would make the work impossible, and because two
earlier sessions in this repository lost time to a full disk.

1. **Prefer `cargo check` to `cargo build`.** Most leaves are type-level: a new
   struct, a new trait, a re-export, a signature change. `cargo check` answers
   the question in a fraction of the time and does not link.
2. **Prefer a focused test to a suite.** `cargo test --test unit <name>` — for
   example `cargo test --test unit issue_1138_concept_lookup` or
   `cargo test --test unit coding_discovery::multilingual` — is the loop. Running
   `cargo test` with no filter compiles and runs 3,542 unit tests and is almost
   never what a single leaf needs.
3. **Let CI run the full matrix.** The macOS lane, the four-client E2E, the box
   language matrix, the full benchmark suites and the WASM size checks are CI's
   job. A leaf is pushed when its own test and its own gate are green locally.
4. **The cheap gates run locally, always.** They need no crate build:
   `rust-script scripts/check-hardcoded-language.rs`,
   `rust-script scripts/check-minimal-core-boundary.rs`,
   `rust-script scripts/check-debt-ratchet.rs --base origin/main`,
   `rust-script scripts/check-file-size.rs`,
   `rust-script scripts/check-seed-registry.rs`. Run them before every commit;
   they are seconds each and they catch most of what this plan set can break.
5. **Never pull a docker image without checking `df` first.** A full
   `konard/box` image is 5.91 GB and CI already deletes SDKs to make room for
   one (`scripts/free-runner-disk.sh:20-26`). Before any `docker pull`,
   `docker build` or box-backed run:

   ```bash
   df -h /private/tmp /
   docker system df          # what is already there
   ```

   If free space is below twice the image size, stop and reclaim rather than
   pull. Plan 06's `install_scoped` applies the same rule to itself: it refuses
   before downloading when free disk is below the procedure's stated
   requirement, and reports both numbers.
6. **One target directory, one toolchain.** `CARGO_TARGET_DIR` points at the main
   clone's `target/` so the worktree does not duplicate a multi-gigabyte build;
   `RUSTUP_TOOLCHAIN=1.98.1` because the crate needs 1.98 and the local default
   is older; `LINDERA_DICTIONARIES_PATH=/tmp/formal-ai-lindera-cache` so the
   Japanese dictionary is fetched once.
7. **Commit with a message file, never `-m`.** Backticks in `-m` are executed by
   the shell, and every commit message in this plan set contains backticked
   identifiers.
8. **Never `git stash` in this shared worktree.** The stash stack is shared with
   the main checkout; use a WIP commit instead.
9. **Regenerate what is generated, in the same commit.**
   `cargo run --example regenerate_self_ast_census` after any `src/` change and
   `rust-script scripts/assemble-requirements.rs --write` after any
   `docs/requirements/` change. Both are checked in CI and both are cheap.
