# Issue #954 (E102) — generated module map, pinned by a doc test

## What landed

The issue's three asks split cleanly into "document now" and "move now":

1. **The generated module map** — `ARCHITECTURE.md §18`, one row per
   module declared in `rust/src/lib.rs` (170 today): name, a one-sentence
   responsibility taken from the module's own `//!` header (with an
   override table for the twenty modules whose files open with code), and
   the owning doc section. Generated by
   `scripts/generate-module-map.rs` (`--write` refreshes the section
   between the markers, `--check` is the CI pin), so the map is
   reproducible rather than hand-maintained.
2. **The pin** — `rust/tests/unit/issue_954_module_map.rs` asserts the
   map's module list equals lib.rs's mod list in both directions: a new
   module fails CI until documented (the issue's exact acceptance), a
   removed module leaves a stale row that fails too. A second test pins
   row shape: every row carries a real responsibility sentence and a
   §-numbered owning section.
3. **The reorganization manifest** — `docs/module-reorganization.md`: the
   exact file→destination tables for the four family moves (`solver/`
   absorbing 17 top-level declarations plus `solver_helpers/` and
   `solver_handlers/`; `world_model/` taking the 1000-line worst offender;
   `dreaming/`; `translate/`), the `mod.rs` re-export rule that keeps
   `cargo public-api` diffs empty, the six live locations of the
   cap-admitting headers each mapped to the move that retires it, the
   measured starting point (273 top-level entries, the 950–1000-line
   band with sizes), and the landing order.
