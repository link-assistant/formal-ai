## Failure analysis and verification

| Requirement | Cause | Change and verification |
| --- | --- | --- |
| Restore English and Russian greetings | The request parser treated the phrase “in a different directory” as a reply-language demand and OpenCode’s “answer it directly instead” as a required output literal. The greeting handler ran and the final constraint projection replaced its answer. | Anchor language recognition to language directives and treat these style clauses as response guidance. The parser fixtures failed against the original code and pass with both prompt shapes. The HTTP suite exercises both greetings across stock-client envelopes and Gemini and Vertex request shapes. |
| Restore OpenCode session titles | OpenCode sends an independent title-generation request. Its “Your output must be:” list introduction became an unfulfillable answer constraint. | Detect the title-generator task from system context and reuse the existing summarizer for a plain single line of up to 50 characters. The OpenCode replay checks English and Russian titles. |
| Restore Claude report execution | The original receipt identifies the Claude Auto mode classifier as the component that declined execution. Formal AI saw the report request and proposed the shell command. The original logs contain no usable classifier verdict. | Select Claude’s ordinary interactive permission mode by default. The user can approve the report command and can explicitly choose another permission mode. Existing structured diagnostics and Claude’s native transcript retain evidence when a selected mode declines execution. |
| Retain background diagnostics for every wrapper | The top-level CLI forwarded its default log level to stderr in `with` mode. The startup and teardown records came from the wrapper process. | Keep typed records in the wrapper log and retain per-dialog records in the temporary server’s capture directory. `FORMAL_AI_LOG_STDERR=1` explicitly requests diagnostic stderr. The wrapper test checks typed records in the log and their absence in ordinary client output. |
| Export client, server, and merged context for the selected session | The report CLI looked up a harness ID, while the server recorded an opening-text-based ID or ran without default dialogue capture. The JavaScript host also omitted its scoped ID callback. Aider and the original community Grok package omit a provider session ID. | Reuse the request identity for recording and report command generation. Read OpenCode’s existing extractor and the native transcript formats for Claude, Codex, Agent, Gemini, Qwen, Aider, and Grok Build. Match Agent and Gemini to a unique recent native transcript. Give clients without an ID a scoped provider URL. Use the selected Codex or Claude transcript for T3 Code. Ambiguous matches produce an export error. The original community Grok process keeps client history in memory and can export the corresponding server history. |
| Describe commands and preserve the GitHub confirmation | Local exports, learning and publication shared generic narration. Output projection could overwrite the final report response. Codex and Gemini can return command narration as an independent assistant message immediately before the tool call. A failed tool response can carry a URL-looking string. | Name each selected report action in five languages. For other shell calls, describe the program and use the seeded command vocabulary to include known subcommands such as `git status` and `git log`. Keep report execution active through split narration and check the tool outcome and exact Formal AI issue URL before confirming publication. The protocol replay exercises successful and failed receipts. |
| Route issue reports from MCP and Telegram | Both adapters passed the report request directly to generic symbolic solving. A local MCP request for `Report issue` produced unrelated web results. | Reuse report-intent recognition and link to the Formal AI issue form for manual review and submission. The public form URL carries no transcript or attachments. The release probe checks English and Russian greetings and the issue form on both HTTP routes. |
| Always verify before deployment | An interactive OpenCode fixture and native client checks existed outside the package publication dependency chain. The browser smoke ran against the already-deployed Pages site. | Both staged publication modes require verification of the selected binary with stock Claude Code, OpenCode, Agent, Codex, Gemini, Qwen, Aider, and Grok Build. Pages and desktop smoke-test their stamped browser assets. The extension and npm release jobs extract their archives and exercise the packaged browser worker. Full and slim container releases check English and Russian greetings and report links over MCP and Telegram in the running images. Workflow regressions check the ordering and required dependencies. |

## Related components and alternatives

- Claude’s gateway contract and permission modes explain why an ordinary report tool call and Auto classification are distinct. An alternate classifier endpoint would require a separate Claude-supported contract and real verdict fixtures. The interactive default keeps the shell approval in Claude and gives report users a supported path. [Gateway documentation](https://code.claude.com/docs/en/llm-gateway), [Claude permission modes](https://code.claude.com/docs/en/permission-modes).
- OpenCode’s provider source already transmits the native ID. The existing OpenCode exporter and canonical Formal AI capture writer can share that ID. A new last-written-file heuristic would leave two active conversations ambiguous. [OpenCode 1.19.5 request source](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/session/llm/request.ts#L187), [OpenCode provider configuration](https://opencode.ai/docs/providers/).
- Agent exposes custom provider headers. Its hosted provider alone supplies a native session header in 0.27.0. The upstream report includes a localhost capture reproduction, a custom-header workaround, and a provider opt-in proposal. [Link Assistant Agent #343](https://github.com/link-assistant/agent/issues/343).
- The historical community Grok package sends neither a session header nor body metadata. A scoped provider URL gives the server a stable identity during an invocation. The upstream report proposes exposing the native identifier from the current project's session store. [Community Grok #361](https://github.com/superagent-ai/grok-cli/issues/361).
- The command path already uses GitHub CLI and the terminal driver already uses Agent Commander. The tests preserve the existing GitHub issue and Gist contracts with a recording replacement for `gh`, so they can run before every release without creating public test issues. [GitHub issue command](https://cli.github.com/manual/gh_issue_create), [GitHub Gist command](https://cli.github.com/manual/gh_gist_create), [Agent Commander](https://github.com/link-assistant/agent-commander).
- Managed terminal integrations share the wrapper’s diagnostic policy. The HTTP suite also exercises both Google request envelopes. Pages exercises its own report link, which carries the conversation in a prefilled GitHub issue. [Managed client catalogue](../../../data/seed/client-integrations.lino), [Pages test](../../../rust/tests/e2e/tests/pages-live-smoke.spec.js).
