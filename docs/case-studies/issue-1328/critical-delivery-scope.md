# Critical delivery scope

The latest owner priority is to unblock usable published releases and the three
original HelloWorld deliveries as quickly as possible. It supersedes the earlier
work order to finish every broader feature first. It changes priorities, not
requirement definitions or the evidence needed to claim delivery.

## Immediate work

- Deliver a usable published release through the existing source-bound release,
  package, runtime and public-download checks. Retain the declared supported
  signing modes and distinguish candidate, merged and released source evidence.
- Complete the exact three original tasks and branches under
  [all eleven issue 1364 requirements](../../requirements/issue-1364-three-client-release.md):
  observed branch ownership; valid tool schemas and bounded failed calls; clean
  build outputs; faithful restart handling; every numbered task obligation;
  truthful toolchain recovery or CI handoff; actual provider errors and exit
  status; same-checkout second-run no-op; owned evidence cleanup; live memory;
  and bounded shutdown. Actual task CI and the prescribed released-client
  evidence remain required. An earlier one-client demonstration is useful, but
  does not complete the remaining clients or establish three-client delivery.
- Apply necessary [issue 1328 fixes](../../requirements/issue-1328-bounded-retries.md)
  and resolve existing merge/release blockers. New coding effort goes to actual
  release or HelloWorld blockers rather than broader speculative improvements.

Existing mandatory CI continues. Failed, cancelled, unknown, skipped and pending
observations are not passes. Keep every prior attempt and its source identity;
never substitute an older success for unverified current-source execution.
This scope adds no acceptance gate and authorizes no skipped check.
