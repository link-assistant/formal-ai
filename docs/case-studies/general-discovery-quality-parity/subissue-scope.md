# Public subissue scope addendum

Audit snapshot: 2026-10-17. This supplements the discovery-quality-parity scope; it records requirements, not implementation acceptance. The starting public hierarchy contained 80 open Formal AI issues and 114 child edges. The earlier 92-body matrix is separate from the 97 additional bodies reviewed here: 56 supplied hierarchy bodies, 24 previously unread Formal AI descendants, and 17 directly relevant external dependency bodies. Of these 97, 77 are Formal AI issues observed CLOSED and 20 are external issues (18 CLOSED, two OPEN). No runtime acceptance was remeasured for this addendum.

The companion [scope ledger](subissue-scope.lino) records every reviewed public URL, observed state, SHA-256 of the exact UTF-8 issue body, recorded parent edges and acceptance boundary. Hashes identify the reviewed body snapshot; they prove neither authorship nor delivery. Raw bodies, private evidence links, personal paths and session identifiers are excluded. A missing parent is explicitly unrecorded, not inferred from prose.

## Closed issues still require acceptance evidence

CLOSED is GitHub metadata, not proof that the current maintained consumer passes the original request. In particular, #1021 requires genuine coding and a real green self-generated PR, #1085 retains broad D1-D9 architecture and delivery obligations, and #710 requires current revalidation of closed requirements. The audit read all previously unread children of these three nodes; each fetched Formal AI child reports zero children. Their other already-cached open children remain part of the earlier matrix. This is a bounded traversal, not a claim that every historical closed issue in the repository was rediscovered.

#1085 explicitly absorbs #710, #958 and #959: consolidation is not verification. Historical canonical-WASM/Rust prescriptions in #658, #936 and #952 need explicit reconciliation with later JavaScript-first/three-root architecture. Their parity and ownership acceptance cannot silently disappear. Actual engine behavior, held-out task execution, source identity, permission boundaries and complete artifacts remain distinct from fixture coverage or documentation. Supplied-recipe execution receives zero autonomous authorship credit in this audit.

## External dependencies and repository boundary

Hive Mind #3282 is a tracking umbrella for correct PRs or honest failures across tools/models. Its broad resource, recovery, synchronization and deployment backlog does not all become required Formal AI source changes. This audit expands only directly relevant client delivery, outcome reporting, provider configuration, error events, attribution, logs, provenance and issue-link safety dependencies; it does not recursively audit unrelated infrastructure. No external code or GitHub metadata was changed.

Hive Mind #3333 (OPEN) owns session-window server/dialog-log collection, sanitized attachment, terminal summaries and actual three-client/sidecar coverage. Formal AI logging support alone does not deliver that external integration. Hive Mind #3334 (OPEN) owns chain transport, client-wide verifier invocation, demanded-attribution failure and post-rewrite verification; local provenance support alone does not deliver it. Agent #332 and Hive Mind #3213 define the recoverable-tool-error boundary; client event compatibility requires actual end-to-end evidence.

Several historical external body banners say reopened/not fixed while current API metadata is CLOSED, including umbrella #3282 and live-delivery #3277. These are separately dated observations, not a reason to rewrite either field or infer acceptance. Readiness must retain real session progress and unknown/failure terminal outcomes; closure automation must preserve intended repository scope and never manufacture cross-repository delivery. No issue closure or pull-request readiness is authorized by this ledger.
