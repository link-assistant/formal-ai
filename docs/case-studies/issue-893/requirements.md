# Requirements trace — issue #893

| ID | Requirement | Evidence |
|---|---|---|
| R893-1 | Define a reproducible seeded sampling protocol over repository files. | `SamplingProtocol` in `src/summarization/validation.rs` sorts and de-duplicates the corpus paths, then permutes them with a seeded `splitmix64` Fisher-Yates shuffle. The draw depends on the seed and the set of paths only — never on the order the caller happened to hand them over — and it is a permutation, so a run never validates the same file twice. `issue_893_seeded_sampling_is_reproducible_and_seed_dependent` asserts reproducibility, caller-order independence, seed dependence and the permutation property. |
| R893-2 | Validate two files per iteration until the result stabilizes or a reported bound is reached. | `DEFAULT_FILES_PER_ITERATION = 2`. `validate_repository_summarization` walks disjoint two-file slices of the permutation, scoring each file through the production summarizer, and stops when `DEFAULT_STABILITY_WINDOW = 3` consecutive iterations all clear the ratchet and sit within `DEFAULT_STABILITY_TOLERANCE_PERCENT = 5` points of one another. Otherwise it stops at `max_iterations` and reports `bound_reached true` rather than claiming a stability it never observed. `issue_893_iterations_validate_two_files_each_until_stable_or_bounded` asserts both exits. |
| R893-3 | Define and publish the quality metric with an 80 percent minimum ratchet. | `CRITERIA` publishes ten named criteria with descriptions, printed by `formal-ai summarization criteria`. `QualityScore` is an exact integer `passed/applicable` ratio, floored — 79.9% gates as 79% — and an empty score is 0, never a vacuous 100. Criteria that cannot apply to a file are dropped from that file's denominator instead of counted as free passes. `QUALITY_RATCHET_PERCENT = 80` plus `ratchet_violations` enforce the published floor *and* monotonicity against the committed `data/summarization/quality-baseline.lino`. Asserted by `issue_893_quality_metric_is_published_and_ratcheted_at_eighty_percent` and `issue_893_committed_baseline_records_the_measured_run`. |
| R893-4 | Exercise recursive Markdown embedded grammars through the production summarizer. | Every sampled file goes through `formalize_repository_file` and `RepositoryFileFormalization::summary` — the production path, not a test double. The `embedded_grammar_recursion` criterion compares the formalization's recursive blocks against an *independent* CommonMark fence scanner (`fenced_block_languages`), so the summarizer cannot grade itself. A run may not declare stability until at least one embedded grammar block has actually been exercised, and `ratchet_violations` rejects a run that recorded none. `issue_893_markdown_embedded_grammars_run_through_the_production_summarizer` asserts all three. |
| R893-5 | Report honestly rather than claiming a stability the run never observed. | `ValidationReport` carries `stabilized` and `bound_reached` as separate facts, keeps every failing criterion together with the evidence detail that produced it, and `to_links_notation` writes exactly what the ratchet later reads back — including `ratchet_runner`, `ratchet_policy` and `honesty_policy`. The two failures the sweep found are recorded in this case study rather than tuned away. |
