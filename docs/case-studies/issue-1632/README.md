## Why the reply failed

The exact-title MediaWiki request returned `missingtitle`. The next request, MediaWiki full-text search, returned HTTP 500. The prior regression supplied a successful full-text response, so it exercised an existing candidate and archive path while skipping the publisher failure. Live probing showed that wikiHow's `Special:LSearch` endpoint still returned the article and its structured parse still contained the instructions. Under the old extraction order, the real article's first section also supplied constipation remedies to an unqualified question. The everyday instructions are in a later section.

The repair builds on the localized source resolution from [PR #1398](https://github.com/link-assistant/formal-ai/pull/1398) and bounded publisher verification from [PR #1622](https://github.com/link-assistant/formal-ai/pull/1622). It reuses the source registry, title relevance rules, capture transport, browser capture component and guide provenance. The language's existing aspect policy expands the search while relevance checks keep the original task. Publisher results contribute steps only after a same-origin candidate's structured article independently passes verification. Section selection uses shared language policy and preserves top-level steps, including supporting details as part of their parent step.

### Research notes and existing components

- **Claude Code auto mode.** The documentation describes a server-side classifier that reviews each action. When a gateway serves the model, Claude Code sends the classifier prompt to that gateway, and "the server returned no safety verdict" is shown when no `<block>` verdict arrives ([errors](https://code.claude.com/docs/en/errors.md#the-server-returned-no-safety-verdict), [gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol.md#feature-pass-through)). Answering the classifier locally was the only way to keep auto mode working without a hosted Anthropic model. The alternative, `--dangerously-skip-permissions`, removes the remaining safety rules, so it was not chosen.
- **Question tools.** OpenCode's `question` tool (`multiple`), Claude Code's `AskUserQuestion` (`multiSelect`) and Codex's `request_user_input` (no multi-select field) differ only in their field names. One payload carrying both flags avoids a per-client branch.
- **Article URLs.** MediaWiki serves articles at `{origin}/wiki/{title}` with `_` for spaces, while wikiHow serves them at `{origin}/{title}` with `-`. Both are stored as data in `data/seed/sources-registry.lino` instead of code.

### Repository gates touched by the follow-up

- **Hardcoded language (R379).** The classifier's block verdict is the seed's `block-template`, so no user-facing text lives in Rust or JavaScript.
- **Notation.** New seed names use dashes (`auto-mode-classifier`, `article-space`).
- **Worker line budget.** The article URL builder lives in `js/worker/formal_ai_worker_source_walk.js` (`sourceWalkArticleUrl`) next to the registry it reads, keeping the how-to worker module under its ceiling.
- **Text summarization ratchet.** The new `отправь`/`отправить` lexemes changed which meaning wins a shared surface in the meaning index, which removed a false duplicate merge. The ratchet was re-based to `duplicates-removed 68` and `issues-duplicates-removed 35`, with the reason recorded in `data/meta/text-summarization-ratchet.lino`. [`summarization-dedup-diff.mjs`](../../../experiments/issue-1632/summarization-dedup-diff.mjs) lists the statements per document.
- **Specification in JavaScript.** Adding `pub mod auto_mode_classifier;` changed the hash of `rust/src/lib.rs`, which 158 generated native programs pin as a source witness. The witness was refreshed the same way as in `cfc16ae9e`. [`spec-case-ids.mjs`](../../../experiments/issue-1632/spec-case-ids.mjs) diffs the extracted cases against `main` (223 carried, all passing).
- **Rust tests locally.** Building the library needs more than the 3 GB memory limit of the development container (rustc is SIGKILLed), so the Rust tests were verified by CI.
