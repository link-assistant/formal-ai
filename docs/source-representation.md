# Source representation and synchronization

The [2026-10-18 source-model doctrine](requirements/doctrine-readable-recursive-source-and-comment-meta-language-2026-10-18.md) governs coding and self-coding. The full recursive source model is a core capability, not a signature census or optional source-formatting utility.

The common meta language holds semantic concepts and their concrete language facets. A source document contains a recursively nested syntax tree whose leaves contain readable source text. Comments, spaces, indentation, delimiters and quote spelling belong to that tree. Parser-internal positions may assist construction, but persisted content must reconstruct itself without original source buffers, numeric node tables or stored offsets. A file's program contains its own actual numeric literals; this rule prohibits replacing content with numeric inventories.

Language-neutral concepts describe the program's declarations, references, types, effects and control flow. Language-specific syntax remains attached as a concrete facet. An unfamiliar construct remains represented exactly with an explicit semantic gap; preserving syntax alone does not prove that its meaning is understood or that it can be translated. A semantic edit must pass target binding, type, effect and operational checks before it can propagate.

## Comments are source and meaning

A comment retains its original readable text, delimiter, whitespace, source attachment and documentation role. Its semantic facet contains formal propositions, relationships, conditions, obligations, references and evidence. Formalizing a comment must expose each unresolved meaning rather than labeling the original prose as a completed semantic representation.

Restoring the original comment uses its concrete facet. Producing an English explanation uses its formal meaning and the naturalization rules. The target's comment-emission rule chooses JavaScript/TypeScript or Rust documentation syntax while preserving that meaning. Re-formalizing generated English must preserve negation, quantification, modality and referenced entities. Formatting equivalence alone cannot qualify this check. Code fragments in comments use nested source models, and links and examples retain their provenance.

## Rules and validation

Parsing, projection, editing, emission and synchronization rules are inspectable Links Notation. Rules name their source concepts, captures, preconditions, target language/context and failure conditions. Language rules run before repository-specific rules; missing rules and ambiguous ownership refuse explicitly. A renderer must never silently return source-language text as a successful translation to another language.

CI reloads persisted content without the source buffer, reconstructs the complete original source, and independently reparses it. It checks semantic projection separately. For edits, it verifies the expected preimage, rejects overlap/capture/ambiguity, emits every affected target, independently validates each target, and exercises the inverse. Held-out inputs cover Unicode, BOM, CRLF, final-newline changes, nested comments where supported, strings/templates/macros, typed declarations, effects and doc-comment naturalization. Rust builds and product execution run only in CI.

Source inventories and diagnostics are derived from content. Checked-in node histograms, line-number inventories and manually refreshed aggregate counts are retired as source-representation authority. Digests may authenticate content but cannot replace it. Existing census-derived planner lookups, collectors and tests must migrate to structural content and stable semantic references; until then they are legacy partial consumers.

The model must support meaningful edits to Formal AI itself and other code through the same operations. A retained supplied controller is execution evidence with zero autonomous-authorship credit. The long-term measure is independently useful coding work from compact task descriptions, with reproducible outcomes and trusted discovery of missing knowledge.

## The codebase is the main reasoning corpus

Formal AI formalizes its own complete code, documentation comments and requirements using the same general path offered for other codebases. Formal statements retain source/construct attachment, conditions, evidence and provenance. Relative meta logic evaluates dependencies and conditional probabilities; shared premises cannot be multiplied as independent evidence. Local code and documentation and trusted public internet knowledge contribute through this same evidence model. Representation fidelity, inferred confidence and observed useful behavior are reported separately.

Documentation and comments are naturalized in English, Russian, Hindi and Chinese. Formal AI selects wording jointly across these languages using measured meaning survival for every ordered round trip, both whole-document and part-by-part. A score preserves the original input terms and denominator, with missing knowledge explicit. It cannot improve by omitting difficult content, copying opaque prose or inserting padding.

Requirements are formalized as scoped obligations, including polarity, quantifiers and conditions. Actual implementation and behavior evidence determines delivered, contradicted, partial or unknown results. The latest authoritative instruction overrides an older genuine conflict for the same scope; prior compatible requirements remain. CI retains the conflicting statements, their evidence and revision ordering, then signals the authorized Formal AI repair path. Verified code may require a documentation change; code that violates current requirements must be repaired rather than described as correct. Unsupported proof obligations stay explicit.

Prefer maintained generators, declarative transformations and bulk automation for source and documentation changes. Ask actual Formal AI to perform tasks it can solve. When it cannot, retain the failed ask and record the missing general capability with its independent expected outcome; improve that capability instead of silently substituting a hand-authored per-task answer. Supplied controllers and recipes remain automation with zero autonomous-authorship credit.

## Current source-content operation

The maintained API is `js/meta/readable-source.js`, with its genuine TypeScript projection. `scripts/source-model.mjs` encodes source as recursive readable Links Notation or reconstructs it from that content, using an explicitly supplied pinned shared meta-language SDK. The command never installs or downloads a compiler. Its default commit identity comes from the existing layered-CI compiler pin. For example, `node scripts/source-model.mjs --from js --input js/meta/readable-source.js --meta-language .meta-language` emits the representation; use `--from meta` on a saved document to reconstruct its source, or `--check` to validate without writing. New output files require `--output` and cannot overwrite an existing file.

The ordinary reader tests retain complete real JavaScript, TypeScript and Rust grammar-derived examples. The shared-compiler CI leg additionally reparses their full recursive content, independently reconstructs them through the CLI, verifies structural edits and exact inverses, rejects wrong syntax metadata, and runs the same operations on actual product sources. This is source-content fidelity and structural editing only: complete workspace migration, general semantic equivalence, formalized comments and multilingual documentation still require their separate implementation and acceptance. Legacy census consumers are not silently reclassified as this new model.

## Documentary comment meanings

`js/meta/comment-meaning.js` and its genuine TypeScript projection add source/owner/role attachments and recursive propositions beside exact comment restoration. Supported compositional clauses retain quantifier order, modality, negation, type constructors and declared effects. `naturalizeComment` renders from that graph and independently re-formalizes both the whole wording and each part. Unknown concepts and unsupported clauses produce explicit needs; citations remain references rather than verified facts. The executable `scripts/probe-comment-semantic-needs.mjs` retains the generic deep-formalization failure instead of claiming that this adapter repairs it. Full code/comment consistency, native integration and four-language project documentation acceptance remain required; see [source comment meanings](architecture/source-comment-meaning.md).

## Complete automated source bundles

The existing whole-source bundle producer now emits a separate readable recursive CST packet for every owned JavaScript, TypeScript and Rust source. Each source path has a .cst.lino.gz packet containing ordinary UTF-8 Links Notation with its complete owner, recursive syntax, comments, whitespace and readable text leaves. Compression is only distribution transport: decompression exposes the actual text representation, not a numeric inventory or encoded source string.

The producer restores each persisted packet without consulting its original source buffer and independently reparses the restored program through its explicitly recorded grammar provider: the frozen Babel parser for JavaScript/TypeScript or the vendored Rust tree-sitter grammar. It compares the exact original source bytes before accepting the file. The stable-release join requires every readable CST packet, binds each owner to the selected release source and refuses missing, changed or substituted content. Legacy network packets remain compatible diagnostics; they cannot replace the required readable CST. CI and release publication use the same maintained producer and independently captured protocol helpers. Final-head hosted execution still has to qualify these changes.

The exported packet restoration API consumes only a receipt and compressed model; it needs no original file. Restoration proves content fidelity. Grammar acceptance is separately performed by the actual producer, and neither result claims general semantic equivalence, complete comment understanding or behavioral parity.

The complete-corpus development probes reconstructed and freshly parsed every selected JavaScript/TypeScript source and every Rust source with a 768 MiB Node heap. The local Babel provider was the already cached 7.29.7; hosted CI installs 8.0.7 from the four-package closure derived from the canonical frozen lock. Each packet records the actual provider version or grammar digest. The pinned shared SDK remains a separate compiler/source-model consumer; its recovery parser exhausted the same local budget on a valid source file, and that failed probe is retained rather than credited as passing. These checks establish source fidelity and syntax acceptance. They do not establish equivalent cross-language behavior, comment understanding, four-language documentation translation, or autonomous authorship.

Use `node scripts/source-model.mjs --frontend complete --from js --input js/meta/readable-source.js --output /tmp/readable-source.cst.lino` for the complete grammar path. The explicit provider does not install dependencies or invoke the shared SDK. The runtime uses the already installed parser, or the directory declared by `FORMAL_AI_CST_RUNTIME`. Reload with `--frontend complete --from meta --input /tmp/readable-source.cst.lino`; the original source may be absent. The persisted owner preserves the original language extension, including TSX. The existing pinned-SDK mode stays separately selectable through `--meta-language`. Both modes reject malformed input and independently reparse reconstructed source.

Operational tooling and packages use the same complete source corpus: scripts, package sources and the Rust build recipe join the three implementation roots. CommonJS .cjs and TypeScript .cts files retain their declared dialect. The CST producer uses the actual recorded grammar providers directly and does not install or require an unused shared SDK; the independent shared compiler checks continue in their own jobs. The compatibility upstreamCommit field records that compiler protocol pin. Source fidelity is qualified by the recursive packet and its actual frontend provenance. The Rust-script Cargo manifest uses the documented crate-comment format (https://docs.rs/crate/rust-script/latest/source/docs/README.md).

The ordinary JavaScript Node host now uses the complete CST frontend for owned Rust self-inspection when no optional SDK is configured. The actual chat planner writes and reads back the recursive planner document, which reconstructs current source exactly; explicit SDK selection still requires its pin and never silently falls back. Unknown modules and traversal remain refused. This does not expand the separate generic dogfood driver’s creation authority: its canonical generated-document request currently remains unowned and refused. The independent chat-tool protocol and driver have different acceptance here; rust/tests/web/default-self-cst.test.mjs preserves both outcomes.
