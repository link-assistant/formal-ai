# R2: comparing every CI/CD file against the five pipeline templates

Issue #1081 asks for more than a bug hunt:

> Use all the best practices from CI/CD templates (check full file tree to
> compare for all GitHub workflow and CI/CD scripts file) […] We should compare
> all files, so we don't have more CI/CD errors in the future and reuse all the
> best practices from these templates.

This file is the record of that comparison. It is a comparison in **both**
directions -- what this repository is missing that a template has, and what a
template is missing that this repository (or another template) has -- because
only the second direction produces the upstream reports requirement R3 asks
for.

## 1. Method

Five trees, read at the commits in `../references/templates/*.HEAD`, which were
still the upstream default-branch tips while every measurement here was taken
(the check is in that directory's README). The trees themselves are the ones
issue #1079 snapshotted, at
`../../../../1079/pulls/1080/references/templates/<lang>-template/`.

Three passes, none of them a spot check:

1. **Every path.** `template-file-inventory.tsv` -- 375 distinct paths across
   the five templates, each row saying which templates carry it and which file
   in this repository answers it. Generated by
   `../../../../../../../experiments/template-ci-comparison.py`.
2. **Every capability.** `template-capability-inventory.tsv` collapses a path
   to what it *does*, so `scripts/check-file-size.rs` and
   `tests/check-file-size.test.js` are one row. This is the pass that finds a
   control implemented under a name this repository would never have grepped
   for.
3. **Every dimension that can be counted.** `template-dimensions.md` -- job
   caps, step budgets, checkout hardening, action pinning, zizmor invocations,
   concurrency groups, terminal status jobs -- as numbers, per template, next
   to this repository's numbers.

Textual diffs of the four workflow files this repository shares with the rust
template are in `template-diffs/`. They are diffs against **rust** because that
is the template whose language and release shape match (`cargo publish`, a
crates.io wait, a desktop packaging lane); the other four templates enter
through passes 2 and 3, which are language-independent.

## 3. Adopted into this repository

### 3.1 `scripts/test-scripts.sh` (from the rust template)

The rust template ships `scripts/test-scripts.sh`; this repository did not, and
capability pass 2 is what surfaced it -- the file name is not mentioned by any
workflow in either tree, so a path diff alone reads it as one more script.

What it protects against is measurable here: `cargo test` builds this
repository's crates, and `scripts/*.rs` are rust-script programs with their own
`[dependencies]` manifests, so `cargo test` never builds them. Four of them --
`check-hardcoded-language.rs`, `check-wasm-worker-size.rs`, `publish-crate.rs`
and `wait-for-crate.rs` -- carried **23 passing test cases that no CI job ever
executed**. Three of the four are *run* by a gate, without `--test`, which runs
the check and not its tests, so the registry looked complete.

A test suite nobody runs is a false negative with a green tick on it, which is
the subject of this issue. The adopted script derives its selection rather than
listing it (every `scripts/*.rs` with a `cfg(test)` suite that neither the unit
test crate nor a `rust-script --test` gate already covers), and
`tests/unit/ci-cd/issue_1081.rs::every_standalone_script_test_suite_is_run_by_something`
asserts the shell's `--list` output equals the same selection computed in Rust,
so the two cannot drift.

### 3.2 `release-preflight` (from no template -- from principle 16)

Requirement R4 points at `CI-CD-BEST-PRACTICES.md`, whose principle 16 is
"Prove You Can Publish Before You Build". No template implements it and neither
did this repository: every publishing credential was first exercised by the
step that uses it, after the pipeline had already spent its capped build
minutes. The measurements, the five registries' actual answers to a write
probe, and why a *login* is not the same signal (Docker Hub answers a
`pull,push` scope request with 200 and a pull-only `access` claim) are in
`../upstream-reports/templates-no-release-preflight.md`.

Implemented here as `scripts/preflight-credentials.sh` plus the
`release-preflight` job, covered by `tests/unit/ci-cd/issue_1081/release_preflight.rs`
and the case runner in `../../../../../../../experiments/issue_1081_preflight/`.
Filed upstream against all five templates (rust#167, js#181, python#77, php#11,
csharp#57).

## 4. Present in a template, deliberately not adopted

Recorded so the next round does not re-litigate them.

| capability | templates | why not |
|---|---|---|
| `scripts/release-naming.rs` | rust, js, python, csharp | It selects a tag prefix for a **multi-language monorepo** (`rust_v` when the language lives in a subdirectory, `v` when it is at the root). This repository is a single crate at the root, so the helper's whole output is the constant `v`. |
| `.changeset/` + `validate-changeset` | js, python, php, csharp | Same job, different mechanism: this repository uses `changelog.d/` fragments with `scripts/check-changelog-fragment.rs` and the `check-fragment-release-map` gate. Adopting Changesets would mean replacing a working release-notes pipeline, not adding a control. |
| `.github/workflows/docs.yml` | python, php, csharp | This repository builds and publishes its documentation from the `deploy-pages` job inside `release.yml`, including the `cargo doc` API reference (issue #479). A second workflow would duplicate the deployment, not cover a gap. |

Two more rows that look like gaps in `template-dimensions.md` and are not:

- **`actions pinned by SHA`: 0 here, 19 in rust.** This repository pins by tag
  (167 sites) and pins its one `docker://` reference by digest -- the only one
  of the six trees that does. SHA pinning across 167 sites is a separate,
  mechanical change with its own review cost; it is not a defect this issue
  found evidence of, and inventing one would be exactly the false positive the
  issue is about.
- **`.github/dependabot.yml`: absent.** Absent in all five templates too, so
  the comparison produces no recommendation either way.

## 5. Present here, missing upstream

Four defects, all filed, all reproduced first:
`../upstream-reports/README.md` carries the table, the per-template evidence
and the cross-references. The measurement transcripts behind them are
`template-artipacked-sweep.md` (checkout credential persistence, measured with
zizmor 1.29.0 in both the configured and the auditor persona) and
`template-dimensions.md` (job caps, wrapped budgets, terminal status jobs).

## 6. What this repository carries that has no template counterpart

Fifteen of its twenty workflows exist for work no template models -- the agent
ladders, the benchmark and learning-cycle lanes, the macOS nextest fan-out, the
coverage and question-necessity ratchets, the weekly job-headroom audit. They
are outside the comparison by construction: a template cannot be missing a
control for a lane it does not have. They are *not* outside this issue, and the
defects found in them are in the register in `../README.md` §4.
