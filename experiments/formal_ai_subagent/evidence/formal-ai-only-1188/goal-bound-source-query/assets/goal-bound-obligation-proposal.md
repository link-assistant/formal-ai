The source reader loses the consumer goal. fileReadTaskFor recognizes the first sentence's paths, modeForPrompt falls back to Full, and planDirectFileReads terminates after reading those files with fileReadFinalAnswer's full-source branch. The obligation derivation currently supports literal writes, command-output writes and generated symbolic checks; it has no source-query or source-backed-plan expectation.

Represent the request as owned goals and dependencies. A Read dependency carries its original clause span, exact path, current call/window identity, provider status/completeness, raw bytes and content identity. These observations remain internal inputs. They fulfill a terminal goal only when the goal actually requests those source bytes. A QueryProjection goal additionally requires a supported parsed field/declaration/property projection and source region identity. A VerifiedRun goal additionally requires the actual requested argv, owned root and observed base head, command receipt and status; only explicit zero status permits success. A SourceBackedPlan goal requires actual declaration/interface witnesses connected to the stated goal and supported operations. If that composition contract is missing, return a typed Gap with bounded observation identities and missing capabilities instead of a source dump or fabricated plan.

Reuse the existing loaded role vocabulary and clause/span ownership contracts for classification, Progress.sourceReadFor for exact Read observations, current execution-evidence/obligation expectations for command binding, and final-result provenance for final projection. A fulfilled dependency is not a fulfilled parent goal. Do not infer transport status from source JSON, command success from prose, purity from a callable name, or useful code from final text length. Keep plain full-file Reads and all original literal-write behavior unchanged.
